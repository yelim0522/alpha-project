## 0. 한 줄 요약

처음 잡았던 novelty("반응형 스케줄러 대비 선제적 KV 마이그레이션")가 **Pallas(2025)** 에 의해 이미 선점된 것을 확인하고, 주제는 유지하면서 novelty를 **"다중 사용자 선제 마이그레이션의 조율(coordination)"** 로 옮겼다. 그에 맞게 시뮬레이터를 재구축하고, Pallas 공개 수치(K=1–4)로 보정한 뒤, 밀도 스윕·통제실험·ablation·최적성 갭 실험까지 수행하여 초안 v0.4를 완성했다.

## 2. 왜 바꿨나 — Pallas와의 중복 진단

**Pallas (Proactive KV cache migration, 2025)** 가 이미 하는 것:

- 이동 예측으로 핸드오버 **이전에** 대상 서버에 KV를 준비 (선제 마이그레이션)
- prefix는 대상에서 **재계산(prefill)**, suffix는 백홀로 **스트리밍** — 두 방법 결합
- 실제 vLLM 프로토타입에서 K=1–4 사용자로 SIT(Service Interruption Time) 측정
- 결과: 반응형 대비 SIT 크게 감소 (예: K=1에서 ~2.6s → ~0.3s 수준)

초안 v0.2의 공헌 4개 중 **1·2·3번이 그대로 Pallas와 겹침** (반응형의 구조적 한계 규명, 선제 마이그레이션 제안, 반응형 최적과의 비교). 그대로 가면 "Pallas의 재발견"이 됨.

**Pallas가 하지 않는 것(우리가 파고든 틈):**

1. 사용자마다 **독립적으로** 트리거 시점을 정한다 → 같은 방향으로 움직이는 사용자 집단은 **같은 시각에 동시에** 준비를 시작함 (herding).
2. 이 동시 트리거가 대상 GPU prefill 큐와 백홀 링크를 함께 잡아먹어, 준비가 **핸드오버 전에 끝나지 못함** → 선제 마이그레이션인데도 SIT가 다시 커짐.
3. Pallas 논문 자체가 K≤4에서만 평가하고, 다중 사용자 경합을 한계로 언급.

→ 우리의 novelty: **"선제 마이그레이션은 이미 있다. 그것을 여러 명이 동시에 쓸 때 어떻게 조율하느냐"** 가 문제이고, 이를 정식화하고 경량 조율 계획기를 제안한다.

## 4. 시뮬레이터 재구축 요약

### 4-1. 모델 구성 (`sim/environment.py`, `sim/policies.py`)

- **자원**: 서버별 GPU prefill 처리량(토큰/s), 배칭 병렬도 P=4, 서버 간 백홀 대역폭, VRAM 예산(대기 KV 용량)
- **정책 4종**
  - `reactive`: 핸드오버 후 전량 복구 (Pallas 논문의 baseline)
  - `detour`: 상태를 원 서버에 두고 토큰만 우회 전달 (SIT 0, ITL 페널티)
  - `pallas-approx`: Pallas Alg.1 근사 — 예측 리드타임 안에 prefix 재계산 + suffix 스트리밍이 끝나도록 사용자별 독립 트리거
  - `coordinated`(제안): 후보 슬롯마다 EDF 순으로 처리되는 유체 점유 모델로 완료 시각 예측, "내 준비가 남에게 주는 지연(외부효과)"을 β로 가중해 비용 최소 슬롯 선택. 경합 없으면 Pallas와 동일 결정.
- **이동 모델**: `GroupFlow`(같은 방향 소대 이동, herding 유발) / `RandomWaypoint`(독립 이동)
- **예측기**: CVH(등속 헤딩) + 가우시안 잡음 옵션

### 4-2. 이번 주 잡은 버그 (결과 왜곡 원인)

| 버그 | 증상 | 수정 |
|---|---|---|
| 예측 타이밍 | 선제 정책이 "다음" 핸드오버가 아니라 현재 셀 기준으로 예측 | 루프 순서 재구성, `respawned` 플래그 |
| 소대 재생성 | 소대가 맵 밖으로 나가 재생성될 때 리드타임 0인 핸드오버로 처리 | 재생성 시 토큰 리셋, 핸드오버로 안 셈 |
| 자원 이중 계산 | 진행 중 준비를 다시 세어 경합 과대 | 점유 계산 일원화 |
| 트리거 이산화 | `t_remain <= tw` 조건이 그리드 간격 때문에 안 걸려 prep 30% 미발동, wasteMB=0 | Pallas Alg.1과 동일하게 "이번 제어 주기에 이상 트리거 시각이 들어오면 발동" |
| EDF 일관성 | VRAM 여유 시 SIT_max 급증 | 핸드오버 잔여 복구(deadline=now)가 진행 중 준비를 선점하도록 `v_share` 수정 |

| 한계 | 왜 문제인가 | 대응 계획 |
|---|---|---|
| CVH 예측기가 너무 정확 → 기본 설정 prep% 100% | 실제보다 낙관적일 수 있음 | 실제 궤적 데이터(nuScenes/T-Drive 등) 재생 |
| K>4는 외삽 | Pallas가 K≤4만 측정했으므로 우리 K=8–32 결과는 보정된 모델의 예측 | 소규모 vLLM 측정으로 P, 직렬화 비용 확인 |
| 배칭 병렬도 P=4, 활성화 직렬화 선형 가정 | 측정 근거 없음 | P∈{2,4,8} 민감도 + 실측 |
| 시뮬레이션 전용 | Pallas는 실제 프로토타입 보유 | 마이크로벤치로 핵심 상수만 실측 (전체 프로토타입은 범위 밖) |

> 참고: 위 두 항목("예측기가 너무 정확", "P=4 근거 없음")은 결함이 아니라 논문에서 **정직하게 공개한 가정**임. 리뷰어가 물었을 때 "알고 있고, 이렇게 대응한다"고 답할 수 있는 상태.

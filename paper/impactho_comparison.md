# ImpactHO와 본 연구의 차이 (문헌 점검, 2026-09-20)

원문: M. Kim 외, [ImpactHO: Importance-Aware KV Cache Transfer for Multi-User Edge LLM Handover](https://arxiv.org/html/2608.10545v1), arXiv:2608.10545v1, 2026-08-11. 아래 구분은 초록만이 아니라 본문의 시스템 모델(§III), Algorithm 1(§V), 실험 설정(§VI)을 확인한 것이다. 현재 arXiv 프리프린트로 표기한다.

| 구분 | ImpactHO | Pallas | 본 연구 |
|---|---|---|---|
| 이동과 이전 시점 | soft handover의 주어진 전송 창에서 정식 전환 **전에도** 타겟에 KV를 적재할 수 있음. 창의 시작을 사용자들 사이에서 공동 선택하는 변수는 없음 | 예측된 타겟·전환 시각으로 사용자별 준비 창을 선택 | 예측된 전환 시각을 데드라인으로 두고 같은 타겟을 향하는 사용자들의 준비 시작 시점을 공동 계획 |
| 핵심 결정 | 중요도 순서로 보낼 부분 KV의 사용자별·슬롯별 백홀 대역폭, 부족할 때의 승인 | 사용자별 준비 창; prefix prefill과 증가하는 suffix 스트리밍 | 사용자별 시작 시점, 계획된 타겟 GPU·링크 점유, suffix 처리, 승인 |
| 목표·복구 수준 | 제한된 창에서 부분 KV를 받아 평균 추론 정확도를 최대화; 정확도 하락을 허용 | 완전한 추론 상태 복원 후 SIT·ITL과 조기 준비 비용 | 완전한 추론 상태 복원 후 평균·p99 SIT 및 경합 완화 |
| 주된 경합 자원 | 공유 백홀 | 관측된 GPU·백홀 유효율(사용자별 결정) | 공유 타겟 GPU·백홀·준비 VRAM(사용자 간 공동 결정) |

주의할 점: **ImpactHO를 단순한 ‘핸드오버 후 반응형’으로 분류하면 틀린다.** §VI-A는 500 ms 기본 전송 창을 정식 사용자 전환 전에도 사용할 수 있다고 명시한다. 다만 [Algorithm 1](https://arxiv.org/html/2608.10545v1)의 입력은 활성 사용자·수신한 KV 비율·정확도 함수·대역폭·슬롯 길이이며, 이동 예측에서 여러 사용자의 준비 *시작 시각*을 공동 선택하지 않는다. 이는 논문에 적힌 결정 변수로부터의 구분이지, 가능한 구현 전체에 대한 부정은 아니다. 소스에서 중요도 점수를 미리 계산하는 것도 ImpactHO가 인정한다.

따라서 본 연구는 ‘여러 사용자 KV 핸드오버의 최초 공동 조율’, ‘핸드오버 전 이전의 최초 제안’, ‘백홀 배분의 최초 최적화’를 주장할 수 없다. 더 안전한 기여 표현은 **이동 예측으로 주어진 전환 데드라인 아래, 완전한 KV 복구를 전제로 같은 목표 MEC 서버의 GPU·링크 경합을 고려해 여러 세션의 선제 준비 시작 시점을 공동 조율한다**는 것이다.

실험 비교군으로는 당장 동등 비교하기 어렵다. ImpactHO는 부분 KV의 정확도–전송량 절충을 허용하고, 기본 실험은 Qwen3-8B·20 Gbps·500 ms 창·정확도 중심이다(§VI-A). 본 시뮬레이터는 완전한 상태 복원·300 Mbps·SIT/ITL 중심이다. ImpactHO를 비교군으로 넣으려면 부분 KV 사용 시의 정확도 함수, 중요도 순서, 타겟 디코딩 가능 조건을 먼저 구현·검증해야 하며, 현재의 단순 KV 압축 비율은 이를 대체하지 못한다. 현재 우선순위에서는 관련 연구와 문제 차이를 명시하고, 직접 비교는 후속 과제로 두는 편이 타당하다.

남는 검증 질문: 동일한 정확도 조건을 강제했을 때도 시작 시점 조율의 이득이 유지되는가? 반대로 부분 KV를 허용하면 시간 조율과 중요도 기반 대역폭 배분을 결합할 수 있는가? 이는 현재 실험 결과가 답하지 않는다.

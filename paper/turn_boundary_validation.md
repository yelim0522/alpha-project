# 턴 경계 모델의 남은 한계 검증 (2026-09-21)

논문용 그림과 설명은 [초안 v0.11 §5-9](draft.md), 벡터 파일과 재현 방법은 [그림 안내](figures/README.md)에 정리했다. 아래 수치는 기존 실험 결과를 유지한다.

후속 [알고리즘 구현 점검](coordination_algorithm.md)에서는 준비 시작 시 메모리 검사가 미래 점유를 예약하지 않아 예산 초과가 가능함을 확인했다. 아래 결과는 당시 근사 모델의 결과이며 메모리 용량을 항상 지키는 시스템의 결과로 해석하지 않는다. 초안 v0.12에 이 한계를 반영했지만 원자료는 변경하지 않았다.

## 무엇을 바꿨는가

기존 §5-8은 모든 정책에 동일한 토큰·대화 시각을 강제로 재생했다. 이전이 늦어져도 다음 턴이 원래 시각에 생성되어, 대기 시간과 실제 처리량이 분리되는 한계가 있었다.

이번 실험은 이동 경로·초기 문맥·이동 예측·사용자별 작업 표본 순서를 공유하되, 각 정책의 응답 완료 시각을 다음 턴에 반영한다. 반응형 복구와 선제 준비의 잔여 복구 시간에는 생성을 멈춘다. 생각하는 시간은 복구와 겹칠 수 있다. 턴 경계 방식은 현재 답변을 이전 서버에서 끝내고, 다음 답변은 이전이 끝나야 생성한다. 전달 홉의 지연도 생성 속도를 낮추므로 다음 질문은 실제 답변 완료 이후에 도착한다.

턴 경계 직후 이전 시작은 다음 제어 주기에 관측한다. 이전 완료 시각은 주기 내에서 추적한다. `dt=0.25 s` 민감도는 기본 `dt=0.5 s`의 이산화 의존성을 확인한다. 단, 이동·예측도 같은 간격으로 갱신되므로 두 조건은 완전히 동일한 연속 경로를 적분한 순수 수치 수렴 검사는 아니다.

## 실측 자료와 합성 가정

응답 길이는 [Azure 공식 대화 요청 자료](https://github.com/Azure/AzurePublicDataset/blob/master/AzureLLMInferenceDataset2024.md)의 25,202개 표본 히스토그램을 사용했다. 추출·출처·해시는 [자료 설명](../sim/data/README.md)에 있다. **실측 응답 길이의 주변 분포**를 이용한 실험이며 실제 대화나 실제 사용자 생각 시간의 재생은 아니다. 전체 원자료가 아닌 균등 바이트 창 표본의 한계도 남는다.

합성 길이는 평균 128-token 로그정규 분포(log sigma=1), 합성 생각 시간은 25%가 즉시 질문하고 나머지가 로그정규 분포를 따르는 혼합이다. 전체 평균 생각 시간을 4초로 맞췄으며 긴 꼬리를 임의로 잘라내지 않았다. 모든 정책은 동일한 사용자·세션별 난수열을 사용한다. 느린 정책이 실험 종료까지 처리하는 작업 수는 달라질 수 있다.

## 측정값의 의미

- `response_wait_*`: 완전히 관측하고 완료한 **응답별** 생성 중단 시간의 평균/p99. 복구가 생각하는 시간에 가려지면 사용자 대기가 아니다. 이전 사건별 SIT와 분모가 다르므로 §5-8의 숫자와 직접 비교하지 않는다.
- `response_excess_*`: 요청 도착부터 마지막 토큰까지 걸린 시간에서 `출력 토큰 수 / 기본 생성 속도`를 뺀 값. 중단과 전달 지연, 선택적으로 둔 생성 처리량 제한을 함께 반영한다. 첫 토큰 전용 지표는 아니다.
- `responses_completed`, `generated_tokens`: 동일한 관측 시간 동안의 완료 응답 수와 생성량. 평균 지연이 작아도 처리량이 줄 수 있다.
- `observed_wait_s`: 모든 세션에서 실제로 관측한 생성 중단 시간을 합한다. 취소·재진입·종료 때문에 끝나지 않은 대기도 이 값에는 포함한다. 완료 대기 구간의 합 + 검열된 대기 구간의 합과 일치해야 한다.
- `censored_responses`, `censored_wait_*`: 영역 재진입 시 새 세션으로 바뀌거나 관측 시간이 끝나 미완료된 응답/대기. 처음부터 일부만 관측한 초기 응답은 응답별 지연 표에서 제외한다. 따라서 완료 응답의 평균/p99에는 여전히 완료 표본 선택 효과가 남는다.
- `itl_ms`: 실제 생성 토큰 수로 가중한 생성 중 토큰 간격이다. §5-8의 유휴 사용자까지 포함한 시간 단계 평균과 정의가 다르다.
- `retained_kv_gb_s`: 무선 서빙 서버와 추론 서버가 다른 동안 이전 서버에 남은 KV의 적분량(GB·s). 최대 메모리나 전송 바이트가 아니다. `forwarded_tokens`는 이 상태에서 생성한 토큰 수다.

## 남는 자원 모델 한계

`azure-decode240`은 각 서버의 생성 처리량을 240 token/s로 둔 **미보정 민감도 조건**이다. 생성 가능 세션들이 슬롯 동안 이를 균등 분배한다. 실제 GPU 처리량을 측정한 값이 아니며, prefill과 decode의 자원 예산도 아직 분리되어 있다. 캐시 점유량은 기록하지만 준비용 6 GB 예산을 전체 세션 VRAM 한도로 오용하지 않는다. 전체 상주 메모리 승인·퇴거, 모델 가중치, GPU 커널 간섭은 후속 검증이 필요하다.

턴 경계 이전 작업은 여러 주기의 자원 점유를 추적하지만 ctHO 및 선제 정책의 잔여 복구는 기존 폐쇄형 지연 근사를 유지한다. 이번 변경은 그 지연을 대화 시계에 적용한 것이며 모든 이전 경로의 GPU 실행을 같은 수준으로 재구현한 것은 아니다. 선제 스케줄러의 향후 토큰 증가 예측도 기본 생성 속도를 사용한다. 새 사용자 입력의 추가 prefill, 응답 내용·정확도, 실측 대화의 상관관계는 포함하지 않는다.

## 결과: 192명, 600초, 시드 0·1·2

각 칸은 시드별 통계의 평균이다. C는 조율형, T는 턴 경계 방식이다. 응답 대기는 모든 완료 응답(중단 없는 응답 포함)의 통계이며, p99는 최악 사용자별 평균과 다르다.

| 조건 | C 응답 대기 평균 / p99 (s) | T 응답 대기 평균 / p99 (s) | T의 완료 응답 감소율(C 대비) |
|---|---:|---:|---:|
| 고정 128토큰·4초 | 0.192 / 1.392 | 0.109 / 2.388 | 7.65% |
| 합성 가변 길이·혼합 생각 시간 | 0.133 / 1.295 | 0.141 / 2.302 | 10.80% |
| Azure 길이·고정 4초 | 0.094 / 1.161 | 0.052 / 1.409 | 9.68% |
| Azure 길이·혼합 생각 시간 | 0.092 / 1.140 | 0.093 / 1.959 | 11.02% |
| 위 조건 + 서버당 생성 240 token/s | 0.102 / 1.088 | 0.105 / 1.904 | 3.21% |
| Azure 길이·혼합 생각 시간, dt=0.25초 | 0.090 / 1.149 | 0.096 / 1.971 | 10.88% |
| 고정 128토큰·즉시 다음 질문 | 0.192 / 1.474 | 0.562 / 4.260 | 17.26% |

7조건 × 3시드의 모든 대응 비교에서 T의 응답 대기 p99가 C보다 컸다. Azure·혼합 조건의 대응 p99 차이는 평균 0.819 s, 시드 간 표본 표준편차 0.067 s였다. 3시드 결과를 모집단 우월성의 증명이나 신뢰구간으로 해석하지 않는다. 시간 간격을 절반으로 줄였을 때 두 방식의 p99와 완료 응답 감소율의 방향은 유지됐다.

주요 조건인 Azure 길이·혼합 생각 시간에서 대기 외의 비용은 다음과 같다.

![주요 조건에서 네 정책의 지연과 완료량](figures/turn_boundary_main.png)

막대는 시드 평균, 작은 점은 개별 시드이다. 지연은 완료 응답만 포함하므로 아래 미완료 통계와 함께 해석한다.

| 측정값(시드 평균) | 조율형 | 턴 경계 |
|---|---:|---:|
| 완료 응답 수 | 10,240.7 | 9,112.3 |
| 응답 완료까지 추가 시간 평균 / p99 (s) | 0.092 / 1.140 | 0.549 / 9.296 |
| 생성 토큰 가중 ITL (ms) | 66.7 | 80.2 |
| 관측된 총 생성 중단 시간 (사용자 합산 s) | 1,346.8 | 1,085.8 |
| 미완료 응답 수(종료 및 재진입 합산) | 1,902.7 | 2,062.3 |
| 검열된 대기 구간에서 관측한 대기 (s) | 3.1 | 16.7 |
| 원격 서빙 상태에서 남은 KV 적분량 (GB·s) | 0.0 | 18,748.2 |

턴 경계 방식은 총 중단 시간이 더 작아도 전달 지연 때문에 응답을 더 적게 완료한다. KV 적분량 18,748.2 GB·s는 600초 동안 전체 서버 합산 평균 약 31.2 GB가 무선 서빙 서버와 다른 추론 서버에 남아 있었다는 뜻이다. 이는 일반적인 서빙 KV에 더해 무조건 추가된 메모리가 아니라 **배치 위치가 남아 있는 비용**이다. 조율형 0은 이 무잡음 조건에서 원격 서빙을 거의 하지 않았다는 뜻이며, 준비 복제본·이전 중 전체 메모리 비용이 0이라는 뜻이 아니다.

생성 처리량 240 token/s 조건에서는 응답 완료까지 추가 시간 p99가 C 14.850 s, T 15.856 s로 둘 다 커지고 완료 응답 차이가 3.21%로 줄었다. 서버 생성 병목을 강하게 두면 전달·이전 정책의 차이보다 공통 계산 병목이 중요해지는 사례다. 이 수치는 GPU 실측으로 보정되지 않았다.

따라서 현재 근거는 **생각하는 시간에 이전을 숨기는 평균 이점은 존재하지만, 응답 전체의 지연·완료량·꼬리 지연까지 포함하면 턴 경계가 조율형을 대체한다는 주장은 지지되지 않는다**는 것이다. 실제 생각 시간·세션 연속성·GPU 혼합 실행 비용을 모두 검증했다는 뜻은 아니다.

![7조건의 응답 대기 p99와 완료량 비율](figures/turn_boundary_robustness.png)

큰 점/오차 막대는 시드 평균/표본 표준편차이며 신뢰구간이 아니다. 오른쪽은 대응 시드별 완료량 비율의 평균이다. 표의 감소율은 시드 평균 완료량의 비율로 계산하여 집계 방식이 조금 다르다.

## 재현

```sh
cd sim
python3 -m unittest discover
python3 turn_validation.py --seeds 3 --users 192 --seconds 600
```

`turn_validation_v09_seeds.csv`는 시드별 원자료, `_summary.csv`는 시드 평균과 표본 표준편차, `_manifest.json`은 설정·소스·입력 해시를 저장한다. 3개 시드의 p99 평균을 보고하며 전체 사건을 합쳐 계산한 p99나 신뢰구간으로 표기하지 않는다. 기본 실험은 7조건 × 4정책 × 3시드이다.

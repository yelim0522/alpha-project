## 1. 목표와 우선순위

**여러 이동 사용자가 같은 MEC 서버에 KV를 미리 준비할 때, 사용자 간 준비 시점 조율이 자원 경합과 서비스 중단 시간을 줄이는지 검증.**

기존 3~5일차 계획에 교수님이 제안한 메모리 예약·할당 및 KV 이전 비교군 검토를 통합함. 모든 비교군을 이번 주에 구현하지 않고, 핵심 효과 확인 후 확장하는 순서.

> 메모리 안전성 확인 → 비교 조건 통일 → 기능별 효과 검증 → 사용자 수 확장 → 제한된 최적해 비교 → 문헌 기반 비교군 추가

검증할 질문은 세 가지로 구분함.

1. **조율 효과:** 단순히 일찍 시작하는 것보다 사용자들의 시점을 함께 정하는 것이 유리한가?
2. **예약 효과:** 미래 증가량 예약이 동적 할당·통계 기반 예약보다 효율적인가?
3. **이전 방식과의 관계:** KV 이전 자체를 개선해도 조율의 추가 이득이 남는가?

메모리 예약을 조율형만의 기능으로 취급하지 않음. 핵심 기여는 **이동 시한과 공유 자원 점유를 고려한 다중 사용자 준비 시점 선택**으로 유지함.

## 3. 3일차: 공정한 비교군 구성

### 발표·본문에 보여줄 네 단계

| 단계 | 정의 | 확인 목적 |
|---|---|---|
| Pallas-aligned | 독립 준비, 잔여 복구만 최종 방식과 통일 | 공정한 독립 준비 기준 |
| 단순 조기 시작 | 위 기준보다 고정된 시간만큼 앞당겨 시작 | ‘그냥 일찍 시작한 효과’ 통제 |
| Timing coordination | 다른 사용자들의 계획을 보고 시작 시점만 분산 | 사용자 간 시점 조율의 효과 |
| Full coordinated | 예상 GPU 점유·외부효과·suffix 처리 선택·EDF를 포함 | 최종 핵심 방식의 효과 |

**첫 막대는 원본 Pallas가 아니라 복구 조건을 맞춘 Pallas 근사 변형임을 표시.** 원래 복구를 유지한 Pallas-approx(P0)도 별도로 남겨 Pallas-aligned(P1)와의 차이를 보고함.

### 네 단계만으로 숨기면 안 되는 차이

- 기존 `abl-planned-k`에는 GPU 점유 인지가 포함되어 있어 순수 Timing-only로 이름만 바꾸지 않음.
- Timing-only는 별도 명세·구현 필요. 다른 사용자들의 계획된 시작 시각을 이용하되, 동적 GPU 점유 추정·외부효과·suffix 선택·EDF는 사용하지 않는 통제로 설계함.
- 분산 간격, 사용자 처리 순서, 준비 창 밖으로 밀릴 때의 처리 규칙은 결과를 보기 전에 확정·기록함. 모든 작업의 직렬 처리나 전환 전 완료를 강제하지 않음.
- Full과 Timing-only의 차이는 여러 기능의 묶음임. 이를 전부 ‘시점만의 효과’로 설명하지 않음.
- [기존 평가 설계 §6](coordination_algorithm.md#6-기존-ablation을-그대로-timing-only라고-부르면-안-되는-이유)의 계획 유지 → 점유 인지 → 외부효과 → suffix 선택 → EDF 사다리를 상세 검증에 유지함. 새 Timing-only는 이 사다리와 구분된 통제군으로 이름을 부여함.
- 192명 고경합 조건에서는 Full에서 각 요소를 하나씩 끄는 비교도 수행해 누적 사다리의 해석을 보완함.

### 공통 조건과 의도적으로 바꾸는 조건

- 동일한 이동·예측 표본, 요청 입력·생성 길이 표본, 자원 용량, 제어 간격, 최대 준비 창, 활성화 비용 사용.
- 전환 후 **잔여 복구**와 `reserved-v1` 승인·확대·취소·반환 규칙을 전 비교군에 동일 적용.
- 전환 전 **suffix 전송/지연 선택**은 기능별 비교 요소로 구분. 잔여 복구 통일과 혼동하지 않음.
- EDF를 추가하기 전 단계는 동일 GPU 실행 순서 사용. 메모리 승인 순서와 GPU 실행 순서는 별도 설정으로 기록.
- 단순 조기 시작의 당김 폭은 평가 결과를 보기 전에 고정. 여러 폭을 비교하면 전체 결과를 공개하고 최선값만 선택하지 않음.
- detour는 주 비교에서 끔. 예측 오류 대응 확장은 별도 실험으로 분리.
- 주 실험의 대화 시계 모드를 고정·기록. 정책별 시계를 쓰면 입력 표본은 공유하되 실제 생성·완료 시각까지 같다고 주장하지 않음.

완료 기준: 설정 차이 표, 변형별 동작 검사, 동일 입력에 대한 공통 메모리 승인·잔여 복구 일치 검사 통과. 이 단계에서는 성능 우위를 완료 조건으로 삼지 않음.

## 4. 4일차: 핵심 실험

### 실행 순서

1. **192명 × 8K 문맥 × seed 3개:** 네 단계 및 상세 기능별 비교부터 수행.
2. 용량·생명주기 검사, 완료/미완료 집계, 복구 조건 일치를 확인한 뒤 결과 원인 점검.
3. 검사가 정상이라면 **32·64·128·192명 × 8K × seed 3개**로 네 단계 비교 확장. 주 표는 48회이며, 조건이 완전히 같은 192명 실행은 재사용 가능.
4. 시점 조율 효과가 없거나 역전되면 해당 결과를 보존하고 원인을 분석. 개선을 만들기 위한 사후 설정 변경 대신, 가설·수정 버전·재평가 조건을 별도로 기록.
5. 전체 체제 지도·대규모 민감도 실험은 핵심 결과를 해석한 이후로 미룸.

### 지표

| 종류 | 기록 항목 |
|---|---|
| 사용자 영향 | 평균 SIT, p99 SIT, 중단 사건 수, 완료·미완료 응답 |
| 동시 경합 | 실제 동시 스트림 첨두 및 시간 분포, GPU 대기 |
| 시점 변화 | 계획/실제 시작, 최초 보류부터 승인까지의 대기, prefix 완료 시각 |
| 메모리 | 예약/실사용 첨두, 보류 시도와 연속 보류 구간 수, 확대 실패 취소, 미사용 예약량×시간 |
| 부작용·비용 | 전송량, 취소된 준비의 실제 낭비, 필요 시 ITL, 계획기 실행시간 |

기존 `memory_start_lag_mean_s`는 최초 보류 이후의 전체 대기와 다르므로 혼용하지 않음. 아직 없는 관측 지표는 실험 전에 구현 여부를 확인하고, 미측정값을 0으로 채우지 않음.

각 seed의 결과와 정책 간 짝지은 차이를 저장함. p99의 사건 단위·계산 범위와 seed별 요약 방식을 명시하고, 세 seed의 p99 평균을 전체 사건의 p99라고 부르지 않음. seed 3개는 초기 검증이며 작은 차이에 통계적 우위를 단정하지 않음.

## 5. 5일차: 제한된 최적해 비교 및 결과 정리

### 작은 문제에서만 전수 탐색

처음에는 작업 3개처럼 작은 사례부터 시작하고 탐색량을 확인한 뒤 확장함. 비교 대상은 **시작 시점만 선택하는 제한된 이산 문제**로 고정함.

양쪽에 다음 조건을 동일 적용함.

- 후보 시작 시각 집합, 제어 격자, 후보 끝점·동률 처리
- suffix 처리, 전환 후 잔여 복구, GPU 실행 순서
- 메모리 예산·승인·확대·반환 및 보류/취소 처리
- 입력 예측과 이용 가능한 정보, 비용 가중치와 평가 목적함수

탐욕 방식이 선택한 스케줄도 전수 탐색 공간에 포함되는지 검사함. 우선 예측·입력을 고정한 문제에서 비교하고, 실제 미래를 아는 해와 온라인 정책을 비교하면 **미래 정보가 있는 참고 하한**으로 별도 표시함.

예시 평가 목적함수는 `Σ(0.8 × SIT + 0.2 × 조기 노출)`로 사전 고정 가능. 국소 외부효과 대용치 자체의 전역 최적화로 해석하지 않음. 최적 목적값이 0이면 상대 격차 대신 절대 차이 보고.

인스턴스별 입력, 최적/탐욕 스케줄, 실제 시작 시각, 비용, 예약 검사 결과를 저장함. 조건이 통일되지 않으면 최적성 수치를 발표하지 않음. 작은 문제의 경험적 격차이지 Full 전체의 근사비 보장이 아님.

### 표·그림·초안

- 알고리즘 정의와 네 단계 차이를 한 표로 정리.
- 핵심 그림 1개: 고경합 조건의 평균/p99 비교 + 사용자 수 증가에 따른 p99 변화. 원자료와 재생성 설정 연결.
- 상세 기능별 표, 메모리 낭비·취소 표, 제한된 최적해 비교 표 추가.
- 초안의 알고리즘, 기능별 비교, 메모리 제약 범위, 최적해 비교, 한계 갱신.
- 기존 ‘최적해 대비 7~8%’는 검증된 새 수치로만 대체. 미완료 시 보류 표시 유지.

## 6. 교수님 피드백 반영: 문헌 기반 비교군 확장

### 6-1. 후보와 우선순위

| 후보 | 가져올 아이디어 | 활용 순서·범위 |
|---|---|---|
| PagedAttention / vLLM, SOSP 2023 | KV가 늘 때 필요한 메모리 블록을 추가 할당 | 첫 추가 실험: 동적 할당 원리를 참고한 비교군 |
| Robust KV Cache Management, arXiv 2026 | 부족 예약과 과잉 예약의 비용, P95·최대량 예약 비교 | 첫 추가 실험: 통계 기반 예약 통제. 전체 최적화 재현은 후순위 |
| S³, NeurIPS 2023 | 출력 길이 예측에 따른 요청 배치·메모리 활용 | 관련 연구 우선. 예측기 학습 자료와 평가 기반 마련 후 구현 검토 |
| EdgeFlow, ICDCS 2026 | KV 직접 전송과 중간 계산값 전송 후 재계산의 조합 | 이전 방식 추가 시 우선 후보. 목적지 고정 근사로 범위 제한 |
| Llumnix, OSDI 2024 | 실행 중 KV의 다단계 복사와 요청 재배치 | 공개 코드 참고 및 후속 이전 비교 후보 |

PagedAttention·Llumnix는 공개 코드 확인. EdgeFlow·Robust 논문은 조사한 출처에서 공식 코드를 확인하지 못했음. Robust는 확인된 출처 기준 사전공개 논문으로 표기하고 학회 게재 논문과 구분함.

### 6-2. 추가 A: 메모리 규칙 비교

핵심 조율 실험이 정리된 뒤, Pallas-aligned와 Full 각각에 다음 규칙을 적용함.

1. 필요량에 따라 추가 할당하는 방식.
2. 과거 자료의 P95에 근거한 예약.
3. 사전에 정한 최대 증가량을 예약하는 보수적 통제.
4. 현재 `reserved-v1`의 이동 시한 기반 증가량 예약.

**이 실험에서는 예약량 산정 규칙이 비교 변수임.** 3~4일차처럼 모든 방식에 동일 예약식을 덧씌우면 차이가 없어지므로 구분함. 용량 상한·자원 쓰기 전 검사·공통 부족 처리·소유자 관리와 반환 규칙은 유지함. 동적 할당 비교도 초과 쓰기를 허용하는 기존 `legacy` 검사로 대체하지 않음.

P95는 지연시간 p99가 아니라 **과거 자료에서 추정한 KV 증가량의 분위수**임. 원 논문의 전체 답변 길이와 달리, 우리 비교에서는 준비 시작부터 전환까지의 기간에 맞춰 정의함. 통계 추정 자료와 평가 자료를 분리하고, 실제 미래 길이를 정책에 제공하지 않음. 최대량의 상한과 생성 속도 가정도 명시함.

메모리 초과 0건뿐 아니라 미사용 예약량·보류·취소·평균/p99 SIT를 함께 비교함. 이를 통해 예약의 안전성과 효율성을 구분함. P95/최대량 통제만 구현하고 Robust의 제안 최적화 알고리즘을 재현했다고 주장하지 않음.

### 6-3. 추가 B: 더 효율적인 KV 이전에서도 조율이 필요한가

EdgeFlow는 관련 연구에 반영하고, 계층별 비용 모델을 검증할 수 있으면 실험 비교군으로 추가함. 이전 목적지는 이동 예측이 정한 서버로 고정하고, **전송·재계산 혼합 기법만 적용한 근사**로 표기함. 전체 목적지 배정 알고리즘이나 2-근사 보장을 가져왔다고 주장하지 않음.

구현 전 확인: 모델별 KV/중간 계산값 크기, 계층별 재계산 비용, 중간값 확보·저장 비용, 통신과 계산의 중첩. 논문 속 특정 가정의 ‘전송량 절반’을 현재 모델에 그대로 적용하지 않음. 현재 토큰 단위 시뮬레이터의 확장이 필요하면 핵심 일정과 분리함.

이전 방식과 조율의 효과를 분리하려면 **동일 이전 기법 × 독립 준비/조율 준비**를 비교함. 반응형 EdgeFlow 근사와 선제 조율형의 단순 차이를 전부 조율 이득으로 해석하지 않음. Llumnix를 추가할 때도 고정 목적지·동일 시작 조건에서 다단계 복사 부분과 전체 부하 분산 정책을 구분함.

| 4일차 | 필수 | 고경합 기능별 결과, 사용자 수 변화 결과, 원인 지표 |

## 8. 재현성과 주장 관리

- 실행마다 정책 버전, 메모리 방식, seed, 전체 설정, 코드 식별자, 원자료·생성 명령 저장.
- 새 결과는 새 파일명 사용. 과거 CSV·그림·초안의 결과를 덮어쓰지 않음.
- 비교 조건이 맞지 않거나 검사에 실패하면 성능 표 확정 중단. 검증 실패와 성능 열세를 구분.
- 준비용 예산 준수를 전체 GPU 메모리 보장으로 표현하지 않음.
- 전환 전 완료, 모든 환경의 우위, 전체 문제의 최적성, 최악 사용자 지연 보장을 주장하지 않음.
- 성능 개선이 작거나 없을 때도 그대로 기록하고, 어느 조건에서 조율이 필요한지로 결론을 한정.

**최종 방향: MEC 이동 상황을 유지하면서, 조율·메모리 예약·이전 기법의 효과를 분리해 설명할 수 있는 실험 구조 완성.**

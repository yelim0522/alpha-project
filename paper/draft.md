# 다중 사용자 이동성 환경 엣지 LLM 서빙을 위한 조율형 선제 KV 마이그레이션: 비조율 선제 스케줄러의 Herding 한계를 넘어서

> 작업 중 초안 (v0.4) — 팀 공통 주제 MEC 하위, 서브주제 "이동성 기반 서비스 마이그레이션 × LLM".
> 방식: 타겟 논문 1편 지정 후 알고리즘/아이디어 개선(방식 B).
> v0.3 변경 요지: Pallas [pallas]의 존재를 반영하여 novelty 축을 이동하였다. v0.2까지의 주장("반응형 스케줄러는 시간축 개입이 불가하므로 선제적 프리페치가 필요하다")은 Pallas가 실제 vLLM 프로토타입으로 이미 확립하였다. 따라서 본 연구의 개선 대상은 반응형 ctHO [target]가 아니라 선제형 Pallas이며, novelty는 "선제성" 자체가 아니라 **공유 자원(백홀 링크·타겟 GPU·VRAM)을 놓고 경쟁하는 다중 사용자의 선제 마이그레이션을 조율(coordination)하는 결정**에 둔다. Pallas는 이를 명시적으로 범위 밖("general multi-user resource allocation remains outside the scope")으로 두었다.
> v0.4 변경 요지: (i) 시뮬레이터의 자원 모델을 Pallas 공개 수치(Table 1, Fig. 8(a))에 보정하고 재현 결과를 5-3절에 수록하였다. (ii) 제안 스케줄러를 "동시성 상한" 방식에서 **계획 점유 기반 유체 모델 + 외부효과 비용** 방식으로 정리하여 $k=1$에서 Pallas와 결정이 정확히 일치하도록 하였다. (iii) 비조율 트리거 동기화를 3-4절에 명제로 정식화하고, 다중 사용자 문제를 3-5절에 정의하였다. (iv) ablation·통제실험·소규모 최적해 대비 격차를 5절에 추가하고 모든 수치를 3 seed 평균으로 갱신하였다.

## 1. 서론

### 1-1. 연구 배경

멀티액세스 엣지 컴퓨팅(MEC)과 그 무선접속망 확장인 AI-RAN은 GPU를 기지국(gNB)에 병설하여 대규모 언어 모델(LLM) 서빙을 사용자 인접 지점으로 끌어온다 [survey1, survey2]. LLM 서빙은 기존 MEC의 상태 없는(stateless) 태스크 오프로딩과 근본적으로 다르다. LLM은 자기회귀적으로 토큰을 생성하며 지금까지의 문맥을 키-값 캐시(KV 캐시)라는 상태로 GPU 메모리에 유지한다. Qwen3-32B의 경우 토큰당 약 256 KiB, 4,000 토큰 문맥에서 약 1 GiB에 이르며, 이 상태는 디코딩이 진행되는 동안 매 토큰 계속 자란다 [pallas]. 사용자가 셀 경계를 넘어 서빙 gNB가 바뀌면(핸드오버) 상태는 원 서버에 남고 사용자는 새 서버에 붙으므로, 세션을 이어가려면 상태를 어떻게든 새 서버에 마련해야 한다.

### 1-2. 문제 제기: 반응형에서 선제형으로, 그리고 남은 문제

핸드오버 후 타겟에서 KV 캐시를 복원하는 방법은 세 가지 계열로 정리된다. 전량 전송(Full-Copy), 원본 토큰만 넘겨 타겟에서 prefill로 재계산(Recomputation), 그리고 둘을 결합하여 prefix는 재계산·suffix는 전송하고 다중 사용자 간 백홀 대역폭까지 함께 배분하는 ctHO [target]이다. 이들은 모두 **핸드오버가 일어난 뒤에야 복구를 시작하는 반응형(reactive)** 이라는 시간 구조를 공유하며, 복구 시간이 그대로 서비스 중단 시간(Service Interruption Time, SIT)이 된다.

Pallas [pallas]는 이 시간 구조를 깨뜨렸다. 이동 예측으로 타겟 gNB와 핸드오버 시각 $\hat{t}_{HO}$를 추정하고, 핸드오버를 "복구의 트리거"가 아니라 "준비의 데드라인"으로 취급한다. 트리거 시점에 토큰열을 안정 prefix(타겟에서 prefill 재계산)와 진화하는 suffix(소스에서 KV 블록 스트리밍)로 나누고, 두 작업을 소스의 디코딩과 병행한다. 온라인 스케줄러는 관측된 유효 prefill 처리량·디코딩 속도·백홀 goodput으로 prefetching window $T_w$를 선택한다. vLLM 프로토타입에서 ctHO 대비 SIT를 2.3–6.8배 줄였다. 즉 "선제성"이라는 결정 축은 이미 점유되었고, 단일 사용자 관점에서의 핸드오버 문제는 상당 부분 해소되었다.

그러나 Pallas의 스케줄러는 **사용자별로 독립적으로** 동작한다. 여러 사용자가 같은 타겟을 향할 때 각자의 $T_w^*$는 (i) 동일한 목적함수, (ii) 동일한 관측 자원 상태, (iii) 근접한 $\hat{t}_{HO}$로부터 계산되므로 거의 같은 값이 나오고, 결과적으로 거의 같은 순간에 트리거된다. N개의 prefix prefill이 타겟 GPU로, N개의 suffix 스트림이 같은 백홀 링크로 동시에 몰린다. **첨두는 사라진 것이 아니라 핸드오버 시점에서 prefetching window 시점으로 옮겨진 것이다.** 게다가 Pallas가 경합을 인지하는 경로는 EWMA로 평활한 *관측* 유효율($r_p, B$)뿐이다. 이는 경합이 시작된 뒤에야 낮아지는 지연 지표이므로, Pallas는 핸드오버에 대해서는 선제적이지만 **경합에 대해서는 여전히 반응형**이다. 논문 자신도 "GPU 사이클이나 gNB 간 대역폭을 동시 마이그레이션 간에 공동 배분하지 않으며, 일반적 다중 사용자 자원 배분은 범위 밖"이라고 명시하고, 결론에서 "동적 다중 사용자 경합 하의 공동 자원 배분과 window 재계획"을 향후 연구로 남겼다. 동시성 실험도 같은 타겟으로 K ≤ 4명에 그친다.

본 연구는 바로 이 자리를 다룬다. 이동성이 공간·시간적으로 상관된 환경(차량 플래툰, 버스, 열차, 출퇴근 흐름)에서 수십~수백 사용자의 핸드오버가 근접 시점·동일 방향으로 겹칠 때, 비조율 선제 스케줄링이 만드는 herding을 규명하고, 타겟 단위로 프리페치 시점·suffix 처리 방식·prefill 순서·VRAM 승인·migrate/detour 선택을 공동 결정하는 조율형 선제 마이그레이션을 제안한다.

### 1-3. 연구 공헌

- 첫째(문제 규명), 선제형 KV 마이그레이션의 대표인 Pallas가 사용자별 독립 결정과 관측 기반 경합 추정이라는 두 구조적 가정 때문에, 다중 사용자 핸드오버가 시간적으로 겹치는 구간에서 첨두를 제거하지 못하고 시간축 상에서 이동시킬 뿐임(herding)을 명제로 정식화하고(3-4절), 이 한계가 파라미터($T_{\max}$, $\alpha$, EWMA 계수) 재조정이나 GPU 서비스 순서 변경으로 해소되지 않는 **결정 구조(비조율)의 문제**임을 통제실험으로 뒷받침한다. Pallas 공개 수치에 보정된 시뮬레이터로 외삽하면, 같은 타겟으로 동시 이동하는 사용자가 32명에 이를 때 비조율 선제 마이그레이션의 SIT가 반응형 ctHO를 넘어선다.
- 둘째(핵심 기여), Pallas의 사용자별 목적함수를 그대로 두되, 타겟 단위에서 후보 사용자의 트리거 시점을 데드라인 순으로 공동 계획하는 조율형 스케줄러를 제안한다. 각 window의 prefill 완료 시각을 **계획된(관측이 아닌) GPU 점유 프로파일** 위에서 타겟의 서비스 규율(EDF)을 따르는 유체 모델로 계산하고, 그 window가 이미 계획된 다른 준비에 떠넘기는 지연(외부효과)을 비용에 더해 트리거를 시간축으로 분산한다. 링크 부하 계획에 따라 사용자별 suffix 처리(스트리밍 vs 지연 재계산)를 선택하고, 타겟 GPU는 EDF 순으로 prefill을 서비스하며, VRAM 예산으로 조기 준비를 승인하고, 예측 불일치·핑퐁 핸드오버에는 migrate 대신 detour를 택한다. 후보가 하나뿐인 구간에서는 Pallas와 **동일한** 결정을 내리므로 제안은 Pallas의 일반화이다.
- 셋째(비교 검증), Pallas의 Table 1과 Fig. 8(a)를 ±10% 이내로 재현하는 보정된 시뮬레이터 위에서, 동일한 예측기·비용 모델·자원 모델로 Full-Copy, Recomputation, ctHO, Detour, Pallas 근사, 제안 방법을 비교하고, Pallas 프로토타입(GPU 2대, K ≤ 4)이 다룰 수 없는 규모(서버 6개, 사용자 32–192명, 플래툰 이동)에서 밀도 스윕·ablation·예측 잡음·이동 모델·모델 크기 변화를 수행한다. 소규모 인스턴스(K=3–5)에서는 트리거 스케줄 전수 탐색과 비교하여 제안의 최적해 대비 격차가 평균 7–8%임을 보인다.
- 넷째(다층 검증), Pallas의 SIT/ITL/$T_{\mathrm{early}}$/$T_{\mathrm{waste}}$에 다중 사용자 구조를 직접 포착하는 지표(링크별 동시 스트림 첨두, 시간축 부하 변동계수, worst-user SIT, 사용자별 SIT의 Jain 공정성 지수, 준비 사용/미사용 분리 SIT)를 더한 지표 계층을 제시한다.

## 2. 관련 연구

### 2-1. LLM 서빙 시스템의 KV 캐시 관리
연속 배칭 [orca], PagedAttention [vllm], 데이터센터 내 요청 마이그레이션 [llumnix], 토큰 기반 상태 복원 [sllm], KV 압축·스트리밍 [cachegen] 등이 KV 캐시를 옮기거나 재구성하는 기본 메커니즘을 제공한다 [kvsurvey, kvsched, mtds]. 그러나 이들은 데이터센터 내부의 처리량·메모리 최적화를 목표로 하며, 무선 이동성에 의한 서버 간 세션 연속성이나 대역폭이 제한된 gNB 간 링크는 고려하지 않는다.

### 2-2. 이동성 기반 서비스 마이그레이션
핸드오버 예측과 서비스 마이그레이션의 결합 [hopred], 궤적 예측·심층강화학습 기반 선제 마이그레이션 [srcl, magrl, mapsm], 5G 상태 유지 애플리케이션의 즉시 이동성 [warp] 등이 제안되어 왔다. 이들은 상태를 고정 크기 객체로 가정하며, LLM 세션 특유의 (i) 토큰 수에 비례하고 준비 중에도 계속 자라는 상태, (ii) 전송의 대안인 재계산(prefill)이라는 선택지를 다루지 않는다.

### 2-3. 엣지 LLM 핸드오버(직접 관련)
ctHO [target]는 prefix 재계산과 suffix 전송을 결합하고 다중 사용자 간 백홀 대역폭을 배분하여 worst-user 핸드오버 지연을 최소화하는 반응형 joint 스케줄러이다. ILCP [ilcp]는 순환 상태를 압축 전송하여 콜드 스타트를 완화한다. Pallas [pallas]는 이동 예측으로 핸드오버 전에 상태 준비를 시작하는 선제형 프레임워크로, 안정 prefix 재계산과 진화 suffix 스트리밍을 소스 디코딩과 병행하고, prefetching window를 온라인으로 선택하며, 예측 변경 시 epoch 기반 취소와 낭비 상한을 제공한다. DAPO [dapo]는 이동성을 고려하나 모델 분할에 초점을 두어 문제 축이 다르다.

### 2-4. 본 연구의 위치
아래 표는 결정 시점과 결정 범위라는 두 축으로 관련 연구를 배치한 것이다. 본 연구는 Pallas와 결정 시점을 공유하되 결정 범위를 사용자별 독립에서 타겟 단위 공동으로 확장한다는 점에서 구별된다. ctHO가 "반응형 × 다중 사용자 joint"였다면, 본 연구는 "선제형 × 다중 사용자 joint"의 빈 칸을 채운다.

| | 사용자별 독립 결정 | 다중 사용자 공동 결정 |
|---|---|---|
| 반응형(핸드오버 후 복구) | Full-Copy, Recomputation | ctHO [target] |
| 선제형(핸드오버 전 준비) | Pallas [pallas] | **본 연구** |

## 3. 시스템 모델 및 문제 진단

### 3-1. 시스템 모델
2차원 평면에 배치된 gNB 병설 엣지 서버 집합 $\mathcal{M}$과 이동 사용자 집합 $\mathcal{K}$를 고려한다. 서버 $m$은 prefill 처리량 $v_m$(토큰/초)의 GPU, 용량 $B_m$(바이트/초)의 ingress 백홀 링크, 그리고 조기 준비 상태에 빌려줄 수 있는 VRAM 예산 $V_m$을 가진다. 사용자 $k$의 문맥 길이 $L_k(t)$는 디코딩 속도 $r_d$로 증가하며 KV 크기는 $c\,L_k(t)$이다. 사용자는 서빙(무선) 서버 $s_k(t)$와 상태를 보유한 앵커 서버 $a_k(t)$를 구별하여 가진다. 둘이 다르면 소스가 디코딩을 계속하고 토큰을 포워딩하는 Detour 상태이며, 홉 수에 비례하는 토큰 간 지연(ITL) 페널티를 받는다 [pallas].

### 3-2. 단일 사용자 비용 모델
**반응형(ctHO).** 핸드오버 시점에 $L$ 토큰 중 $p$를 재계산, $L-p$를 전송하면 두 작업이 병렬이므로

$$
D(p)=\max\!\left(\frac{p}{v},\ \frac{c\,(L-p)}{B}\right),\qquad
p^\star=\frac{c\,v\,L}{B+c\,v},\qquad
D^\star=\frac{c\,L}{B+c\,v}.
$$

**선제형(Pallas).** 예측 핸드오버 시각까지 남은 시간 $\hat{T}_{\mathrm{remain}}$에서 window $T_w$를 택하면 트리거 시점의 prefix 길이는 $\hat{L}_{\mathrm{hist}}(T_w)=K+r_d(\hat{T}_{\mathrm{remain}}-T_w)$이고,

$$
T_{\mathrm{hist}}=\frac{\hat{L}_{\mathrm{hist}}}{r_p},\qquad
T_{\mathrm{res}}(T_w)=\max\!\left\{0,\ \frac{r_d\,T_w\,c}{B}-T_w\right\},
$$

$$
T_{\mathrm{SIT}}(T_w)=T_0+\max\{0,\ T_{\mathrm{hist}}-T_w,\ T_{\mathrm{res}}(T_w)\},\qquad
T_{\mathrm{early}}(T_w)=\max\{0,\ T_w-T_{\mathrm{hist}}\},
$$

$$
T_w^\star=\arg\min_{T_w\in[0,\min(T_{\max},\hat{T}_{\mathrm{remain}})]}\ \alpha\,T_{\mathrm{SIT}}(T_w)+(1-\alpha)\,T_{\mathrm{early}}(T_w).
$$

여기서 $r_p, B$는 **관측된** 유효율(타겟 GPU·링크의 현재 경합을 반영해 EWMA로 평활한 값)이다. 핸드오버 시점에 남은 prefix와 미전송 suffix가 SIT를 결정한다.

### 3-3. 다중 사용자 자원 모델
타겟 $m$의 GPU는 두 단계로 모델링한다. prefill 요청 하나는 최대 $v_m$ 토큰/초를 얻고, 여러 요청은 배칭되어 합계 $P\,v_m$까지 처리된다($P$: 배칭 병렬도, 기본 4). 따라서 동시 prefill 수 $n$에 대한 요청당 유효율은

$$
r_p^{\mathrm{eff}}(n)=v_m\,\min\!\left(1,\ \frac{P}{n}\right),\qquad
B^{\mathrm{eff}}(n^{\mathrm{stream}})=\frac{B_m}{n^{\mathrm{stream}}}
$$

이다. $n\le P$까지는 서로 느려지지 않고 그 이상이면 균등 분배된다. 이 형태는 Pallas Fig. 8(a)에서 동시 UE 수 K=1–3에서 SIT가 거의 평평하다가 K=4에서 오르는 관측이 요구하는 것이다(5-3절). 링크는 백로그를 가진 스트림 사이에 $B_m$을 공정 분배한다. GPU 서비스 순서(FCFS 또는 EDF)는 정책이 정한다. 핸드오버 후 반응형 복구와 핸드오버 전 선제 준비가 **같은 자원을 놓고 경쟁한다**. 준비된 prefix의 활성화는 prefill이 아니므로 GPU 지분을 희석하지 않으나, 같은 제어 주기에 여러 준비가 활성화되면 요청당 $\delta$(약 40 ms)씩 직렬화된다(Fig. 8(a) worst-user 수치에서 보정).

### 3-4. 비조율 선제 스케줄링의 Herding: 정식화
같은 타겟 $m$을 향하는 $N$명의 후보 집합 $\mathcal{C}_m$을 생각하자. Pallas는 각 $k\in\mathcal{C}_m$에 대해 3-2절의 $T_w^\star$를 독립적으로 계산한다.

**명제 1 (비조율 트리거의 동기화).** $\mathcal{C}_m$의 사용자들이 (a) 같은 목적함수와 파라미터($\alpha$, $T_{\max}$, 격자), (b) 같은 관측 유효율 $(r_p, B)$, (c) 근접한 데드라인 $|\hat{t}_{HO,k}-\hat{t}_{HO,k'}|\le\epsilon$, (d) 근접한 prefix 길이 $|K_k-K_{k'}|\le\kappa$를 가지면, 선택되는 window는 $|T_{w,k}^\star-T_{w,k'}^\star|\le r_d\,\epsilon/r_p+\kappa/r_p+\Delta T$를 만족하고, 따라서 트리거 시각 $\hat{t}_{HO,k}-T_{w,k}^\star$의 산포는 $\epsilon+r_d\epsilon/r_p+\kappa/r_p+\Delta T$ 이내이다.

*증명 개요.* 3-2절의 $\mathcal{J}(T_w)$는 $T_w<T_{\mathrm{hist}}(T_w)$ 구간에서 기울기 $-\alpha(1+r_d/r_p)$로 감소하고 $T_w>T_{\mathrm{hist}}$ 구간에서 기울기 $(1-\alpha)(1+r_d/r_p)$로 증가하는 조각별 선형 함수이므로(잔여 스트리밍 항 $T_{\mathrm{res}}=0$일 때), 유일한 최소점은 고정점 $T_w=T_{\mathrm{hist}}(T_w)$, 즉 $T_w^\star=(K+r_d\hat{T}_{\mathrm{remain}})/(r_p+r_d)$이다. 이것은 $K$와 $\hat{T}_{\mathrm{remain}}$에 대해 Lipschitz 상수 $1/(r_p+r_d)$, $r_d/(r_p+r_d)$로 연속이고 격자 반올림 오차가 $\Delta T$ 이내이므로 결론이 따른다. $\square$

플래툰의 경우 $\epsilon$은 차량 간 간격/속도(수십 m / 25 m/s ≈ 1–2 s), $\kappa/r_p$는 문맥 길이 차이/prefill 속도(수백 토큰 / 2,000 tok/s ≈ 0.1–0.5 s)이므로 $N$명의 트리거가 1–2 s 안에 몰린다. 반면 각 준비의 prefill 소요는 $K/v_m\approx 1$–2 s이고 배칭 여유는 $P$이므로 $N>P$이면 window 동안 실제 유효율은 $v_m P/N$으로 떨어진다. 그러나 각 사용자는 (b)에 의해 $N\approx 1$인 과거 관측치로 $T_{\mathrm{hist}}$를 계산했으므로 이를 $N/P$배 과소 추정했고, window 안에 prefix를 마치지 못한 채 핸드오버를 맞는다. 잔여 prefix는 반응형 재계산과 같은 경로로 SIT에 들어간다.

**따름정리 (준비 사용 시 SIT 하한).** 조건 (a)–(d)와 $N>P$ 하에서 비조율 스케줄링의 사용자별 SIT는 근사적으로

$$
T_{\mathrm{SIT}}\ \gtrsim\ T_0^{p}+\hat{L}_{\mathrm{hist}}\left(\frac{N}{P\,v_m}-\frac{1}{v_m}\right)+\delta\,(i-1)
$$

($i$: 활성화 순번)로, $N$에 선형으로 증가한다. 5-3절 Part C의 외삽에서 $N=32$이면 이 값이 반응형 ctHO를 넘는다.

요약하면 비조율 선제 스케줄링은 (i) 첨두를 제거하지 않고 시간축에서 앞으로 옮기며(명제 1), (ii) 관측 기반 경합 추정은 지연 지표이므로 첨두 형성을 예방할 수 없고, (iii) 준비 prefill이 반응형 복구와 GPU를 경쟁하여 예측이 없는 사용자에게 외부 비용을 떠넘긴다. 이는 정책 파라미터가 아니라 **결정 범위(사용자별 독립)** 에서 비롯된다.

**통제실험.** 이를 확인하기 위해 고밀도 플래툰 조건에서 Pallas 근사의 파라미터를 재탐색한다: $T_{\max}$ 5→15 s, $\alpha$ 0.8→0.5, EWMA 계수 0.5→0.95(빠른 관측 반응), 그리고 GPU 서비스 순서만 EDF로 바꾼 변형. 재조정 후에도 동시 스트림 첨두와 SIT p99가 개선되지 않으면(5-5절), 한계가 조정 부족이 아니라 결정 구조에서 기인한다는 주장이 뒷받침된다.

### 3-5. 문제 정의: 타겟 단위 공동 트리거 계획
타겟 $m$과 계획 시점 $t$에서 후보 집합 $\mathcal{C}_m$(예측 타겟이 $m$이고 아직 준비가 없는 사용자)과 활성 준비 집합 $\mathcal{A}_m$이 주어진다. 결정 변수는 각 후보의 window $T_{w,k}\in\{0,\Delta T,\dots,\min(T_{\max},\hat{T}_{\mathrm{remain},k})\}$와 suffix 모드 $\sigma_k\in\{\text{stream},\text{defer}\}$이다. 자원 결합은 3-3절의 점유 프로파일로 표현된다. 시간 격자 $b$에서 prefill 중인 준비의 수를 $n_m(b)$라 하면 각 준비의 진행 속도는 $r_p^{\mathrm{eff}}(n_m(b))$(EDF이면 데드라인 순 우선)이고, 이에 따라 완료 시각 $\tau_k$, 잔여 $\max(0,\tau_k-\hat{t}_{HO,k})$, 조기 노출 $\max(0,\hat{t}_{HO,k}-\tau_k)$가 정해진다. 문제는

$$
\min_{\{T_{w,k},\sigma_k\}}\ \sum_{k\in\mathcal{C}_m}\Big[\alpha\,T_{\mathrm{SIT},k}+(1-\alpha)\,T_{\mathrm{early},k}\Big]
\quad\text{s.t.}\quad \sum_{k}c\,L_k\,\mathbb{1}[\text{준비 중}]\le V_m
$$

이다. 즉 Pallas의 사용자별 목적함수를 **합**으로 묶고 자원 결합을 명시한 것으로, Pallas는 결합 항을 무시한($n_m\equiv$ 관측치) 사용자별 분리 해에 해당한다. 후보 수 $N$과 격자 수 $G$에 대해 탐색 공간이 $G^N$이므로 일반적으로 전수 탐색은 불가하고, 4절은 데드라인 순 탐욕 해를 제안한다. 5-6절에서 $N\le 5$ 인스턴스의 전수 탐색과 비교한다.

## 4. 제안 방법: 타겟 단위 조율형 선제 마이그레이션

### 4-1. 설계 목표와 원칙
(i) **조율**: 같은 타겟을 향하는 사용자들의 window를 공동 계획하여, 배칭 여유 $P$를 넘는 슬롯을 피하도록 트리거를 시간축으로 분산한다. (ii) **계획 기반 경합 추정**: 관측 EWMA 대신, 이미 트리거된 준비와 이미 계획된 준비가 각 시간 구간에 몇 개 겹치는지(점유 프로파일)로 완료 시각을 산정한다. 지연 지표가 아닌 선행 지표이다. (iii) **Pallas로의 수렴**: 후보가 하나이고 활성 준비가 없으면 점유가 비어 있어 Pallas의 격자 탐색과 같은 목적함수·같은 격자·같은 트리거 규칙으로 **같은 결정**을 내린다. 즉 제안은 Pallas의 일반화이다(5-4절에서 수치 일치 확인). (iv) **경량·학습 불필요**: 예측기와 사용자별 목적함수는 Pallas 것을 그대로 쓰고, 추가 연산은 타겟별 후보 수 × 격자 수 × 점유 구간 수의 스칼라 연산이다.

### 4-2. 구성 요소
- **타겟 단위 계획기.** 매 제어 주기, 타겟 $m$을 향해 예측되었으나 아직 계획이 없는 후보를 $\hat{t}_{HO}$ 오름차순(EDF)으로 정렬한다. 시간축을 $\Delta T$ 격자로 나눈 점유 프로파일에 활성 준비의 잔여 prefill 구간과 기존 계획의 prefill 구간을 (데드라인과 함께) 먼저 채운다. 각 후보에 대해 window $T_w\in\{0,\Delta T,\dots\}$를 훑으며 아래 비용을 평가하고 최소인 $T_w$를 택한 뒤, 그 prefill 구간을 프로파일에 더하고 다음 후보로 넘어간다. 계획은 예측(타겟·시각)이 바뀌기 전까지 유지되고(sticky), 계획된 트리거 시점이 다음 제어 주기 안에 들면 발사한다. Pallas가 트리거 결정을 일회성으로 두는 것과 대응한다.
- **유체 완료 모델과 외부효과 비용.** window $T_w$의 트리거 시점 $s=\hat{t}_{HO}-T_w$에서 시작하는 $\hat{L}_{\mathrm{hist}}$ 토큰의 prefill을 점유 프로파일 위에서 격자 단위로 진행시킨다. 격자 $b$에 데드라인이 나보다 이르거나 같은 준비가 $n_e(b)$, 늦은 준비가 $n_l(b)$ 있으면, EDF 서비스 하에서 내 진행 속도는 $v_m\min(1,\max(0,P-n_e(b)))$이고(이른 데드라인이 $P$개를 채우면 대기), 내가 배치를 포화시켜 늦은 데드라인의 준비를 밀어내는 격자에서는 그들이 합계 $\Delta T$의 진행을 잃는다. 이렇게 얻은 완료 시각 $\tau$와 외부효과 $T_{\mathrm{ext}}$로

$$
\mathcal{J}(T_w)=\alpha\,\big[T_0^{p}+\max\{0,\ \tau-\hat{t}_{HO},\ T_{\mathrm{res}}\}\big]+(1-\alpha)\max\{0,\ \hat{t}_{HO}-\tau\}+\beta\,T_{\mathrm{ext}}
$$

를 최소화한다. 외부효과 항이 없으면 각 사용자는 포화 슬롯에 그대로 올라타고(자기 잔여만 보므로), 이 항이 트리거를 비어 있는 이른 슬롯으로 밀어내어 staggering을 만든다. $\beta=1$이 기본이며 0.5–4 범위에서 결과가 둔감하다(5-5절). FCFS 서비스를 쓰는 ablation 변형에서는 균등 분배 유체 모델을 쓴다.
- **suffix 처리 모드 선택.** window 동안 생성되는 suffix를 스트리밍할지($T_{\mathrm{res}}^{\mathrm{stream}}$), 스트리밍하지 않고 핸드오버 시점에 짧은 suffix를 최적 분할로 재계산·전송할지($T_{\mathrm{res}}^{\mathrm{defer}}$)를 사용자별로 정한다. 계획된 집계 스트림 속도 $k\,r_d\,c$가 링크 용량의 $\rho$ 배를 넘으면 스트리밍을 금지한다. 이는 링크 첨두를 낮추는 대신 소량의 재계산을 받아들이는 트레이드오프이다.
- **EDF prefill 서비스.** 타겟 GPU는 준비 중인 prefix들을 트리거 순(FCFS)이 아니라 데드라인 순으로 서비스한다. 임박한 사용자가 먼저 끝나므로 같은 총 처리량에서 잔여 prefix가 SIT로 넘어가는 양이 줄어들고, 계획기의 유체 모델과 실제 서비스가 일치한다. 핸드오버 시점의 잔여 복구는 데드라인이 지금이므로 진행 중인 준비를 선점한다.
- **VRAM 승인.** 타겟에 이미 준비된 상태의 합이 $V_m$을 넘으면 트리거를 보류한다. 다수의 조기 prefix가 타겟 메모리를 점유하는 문제는 단일 사용자 Pallas에서는 나타나지 않는다. 계획 지평을 Pallas와 같은 $T_{\max}=5$ s로 두는 것이 VRAM 과점유를 피하는 데도 유리하다(5-5절).
- **migrate 대신 detour.** 예측이 없었거나 예측과 다른 타겟으로 핸드오버가 발생한 경우, 또는 최근 떠난 서버로 되돌아가는 핑퐁인 경우, 준비되지 않은 상태를 반응형으로 복구하는 대신 홉 상한 $h_{\max}$까지 Detour를 택한다. 일정 시간($\tau_{\mathrm{settle}}$) 머무르면 데드라인 없는 배경 마이그레이션으로 상태를 서빙 서버로 옮긴다(settle). 반응형 복구 트래픽을 첨두에서 제거하는 대신 일시적 ITL 상승을 받는다.

### 4-3. 알고리즘 개요
매 제어 주기 $t$:
1. 활성 준비 갱신: 예측 타겟이 바뀐 준비는 취소(epoch 증가), 시각만 바뀐 준비는 데드라인 갱신. 예측이 바뀐 기존 계획은 폐기.
2. Detour 상태로 $\tau_{\mathrm{settle}}$ 이상 머문 사용자는 서빙 서버로 settle 마이그레이션 트리거.
3. 타겟별로 (활성 준비 + 유지 계획)으로 점유 프로파일 구성 → 미계획 후보를 4-2 계획기로 계획 → 트리거 시점이 이번 주기에 든 사용자 중 VRAM 승인을 통과한 사용자만 트리거(모드 포함).
4. 자원 진행: GPU는 EDF로 prefix 서비스, 링크는 스트림 공정 분배, 소스 디코딩으로 suffix 증가.
5. 핸드오버 발생 시: 준비가 타겟과 일치하면 잔여(미완 prefix + 미전송 suffix)를 최적 분할로 복구; 불일치·핑퐁이면 detour 또는 반응형 하이브리드.

계산 복잡도는 타겟당 $O(|\mathcal{C}_m|\cdot G\cdot H)$($G$: window 격자 수, $H$: 점유 구간 수)의 스칼라 연산으로, Pallas의 $O(G)$ 그리드 탐색에 후보 수와 지평 길이가 곱해진 수준이다. 3-5절 문제에 대한 데드라인 순 탐욕 해이며, 5-6절에서 전수 탐색과의 격차를 측정한다.

## 5. 실험 설계 및 결과

### 5-1. 지표 계층화
- **주 지표(Pallas·ctHO와 직접 비교 가능)**: SIT 평균/p99/최대(worst-user), ITL 평균(Detour 비용).
- **구조 지표(다중 사용자 메커니즘 직접 포착)**: 링크별 동시 스트림 첨두, 시간축 링크 요구량의 변동계수(CoV, 버스트성), $T_{\mathrm{early}}$ 평균, 취소로 낭비된 준비량(MB), 준비를 사용한 마이그레이션 비율과 그 부분집합의 SIT(선제 계열의 이득이 어디서 오는지 분리).
- **공정성**: 사용자별 평균 SIT의 Jain 지수.
- **부가 지표**: 총 전송량, detour 횟수, 핑퐁 횟수, 핸드오버 수.

### 5-2. 베이스라인
Full-Copy / Recomputation / ctHO 근사(핸드오버 시점 최적 분할, 다중 사용자 공정 분배) / Detour / **Pallas 근사**(사용자별 $T_w^\star$ 그리드 탐색, 관측 EWMA 유효율, prefix prefill FCFS + suffix 스트리밍, 타겟 변경 시 취소) / 제안(조율형). 모든 정책은 동일한 CVH 예측기, 동일한 궤적·토큰·예측 트레이스, 동일한 자원 모델을 공유한다(paired comparison). 두 선제 정책은 같은 window 격자($\Delta T$=0.2 s), $\alpha$=0.8, $T_{\max}$=5 s, 트리거 규칙을 쓴다.

### 5-3. 환경과 보정: Pallas 공개 수치 재현
**보정 절차.** GPU 2단계 모델(3-3절)의 요청당 prefill 속도 $v_m$과 반응형 활성화 비용 $T_0$는 Pallas Table 1(Qwen3-32B, 300 Mbps, 단일 핸드오버, 1K/2K/4K 토큰의 Full-Copy/Recomputation/ctHO)에 맞추고, 준비된 요청의 활성화 비용 $T_0^{p}$와 동시 활성화 직렬화 $\delta$는 Fig. 8(a)(Qwen3-14B, 2K 토큰, 1 Gbps, 같은 타겟으로 동시 이동하는 UE K=1–4)의 K=1과 K=4 worst-user에 맞춘다. 나머지 셀은 검증에 쓴다. 결과(`sim/reproduce_pallas.py`):

### 5-6. 소규모 인스턴스 최적해 대비 격차
같은 타겟을 향하는 K=3–5명의 문맥(1K–4K)과 데드라인(2–4 s)을 무작위로 뽑고, 배칭 여유를 $P$=2로 좁혀 경합이 생기게 한 뒤, 0.25 s 격자(K=5는 0.5 s) 위의 모든 트리거 스케줄을 전수 탐색하여 3-5절 목적함수의 최적값을 구했다(`sim/optgap.py`, 인스턴스 10개씩). 제안의 격차는 평균 +7.4% / +8.3% / +7.2%(K=3/4/5; 최대 +18%), Pallas 근사는 +19.7% / +50.5% / +73.4%(최대 +204%)이다. Pallas는 데드라인이 겹치지 않는 인스턴스에서는 최적에 가깝고(격차 ≈ 10%, 격자 반올림 수준) 겹치는 인스턴스에서 크게 벌어지는 반면, 제안은 모든 인스턴스에서 20% 이내이다. 탐욕 해가 남기는 격차는 주로 격자 반올림과 늦은 데드라인 후보가 이른 후보의 슬롯을 쓰지 못하는 데서 온다.

## 6. 한계와 향후 과제

- **시뮬레이션 기반.** Pallas는 실제 vLLM 프로토타입으로 검증하였다. 본 연구는 수십~수백 사용자 규모라는 프로토타입이 다룰 수 없는 영역을 다루며, 그 대신 프로토타입이 측정한 구간(Table 1, Fig. 8(a) K=1–4)을 ±10% 이내로 재현하는 것으로 보정의 신뢰를 확보하였다(5-3절). 그러나 K>4 외삽과 다중 서버 환경은 측정으로 뒷받침되지 않으며, 특히 활성화 직렬화 $\delta$의 선형 가정(K=3에서 +15%)과 배칭 병렬도 $P$=4는 GPU·엔진에 따라 다르다. 본실험에서는 $P\in\{2,4,8\}$ 민감도를 추가하고, 가능하면 소규모 vLLM 재현으로 $P$와 $\delta$를 직접 측정한다.
- **자원 모델의 단순성.** 배칭 여유를 넘는 prefill을 균등 분할(FCFS) 또는 데드라인 순(EDF)으로 근사하고 링크를 공정 분배로 근사하였다. chunked prefill과 상주 디코딩 요청(Pallas의 HI 경합)과의 상호작용, 링크의 프로토콜 오버헤드는 반영되지 않았다.
- **예측기.** CVH 외삽만 사용하였고 기본 설정에서는 예측이 거의 정확하여 준비 사용률이 100%에 가깝다. 잡음 실험(5-5절)이 이를 완화하지만 실제 궤적(nuScenes 등)으로의 교체가 필요하다. 예측 신뢰도를 계획에 반영하는 방식(확률 가중 다중 후보 준비, 헤징)은 열린 문제이다.
- **Detour 비용.** 홉당 고정 ITL 페널티로 근사하였고 소스 GPU에 남는 상주 세션의 메모리·연산 비용은 반영하지 않았다. 기본 설정에서는 detour가 발동하지 않으므로 이득과 무관하지만, 잡음 설정에서의 detour 비용(ITL +0.4 ms, 최대 142회)은 실제 비용 모델로 재평가해야 한다.
- **VRAM과 계획의 분리.** VRAM 승인은 트리거 시점에만 검사하므로, 예산이 작고 계획 지평이 길면 계획된 트리거가 보류되어 준비율이 떨어진다(5-5절의 $T_{\max}$=15 s 변형). VRAM 점유를 점유 프로파일처럼 계획에 포함하는 것이 자연스러운 확장이다.
- **탐욕 해의 격차.** 데드라인 순 탐욕 계획은 소규모 인스턴스에서 최적 대비 평균 7–8%, 최대 18%의 격차를 남긴다(5-6절). 후보 간 슬롯 교환(local search)이나 늦은 데드라인 후보의 조기 배치 허용으로 줄일 수 있으나, 제어 주기 내 계산량과의 트레이드오프가 있다.
- **공정성.** 데드라인 순 계획은 원칙적으로 늦게 도착한 사용자를 뒤로 미루지만, 측정된 Jain 지수는 제안이 더 높다(0.98 vs 0.89). 이는 비조율에서 모든 사용자가 함께 느려지는 것보다 조율에서 소수가 조금 이른 노출을 받는 편이 사용자 간 분산을 줄이기 때문이다.

## 7. 결론(예정)
사용자 이동으로 서빙 엣지 서버가 바뀔 때 LLM 세션의 KV 캐시를 잇는 문제에서, 선제형 마이그레이션(Pallas)은 핸드오버를 준비의 데드라인으로 바꾸어 단일 사용자 SIT를 크게 낮추었다. 그러나 사용자별 독립 결정과 관측 기반 경합 추정은 다중 사용자 핸드오버가 겹치는 구간에서 트리거를 동기화시켜(명제 1) 첨두를 제거하지 못하고 앞으로 옮길 뿐이며, 이는 파라미터 재조정이나 GPU 서비스 순서 변경으로 해소되지 않는다. Pallas 공개 수치에 보정한 시뮬레이터로 외삽하면 같은 타겟으로 32명이 동시 이동할 때 비조율 선제 마이그레이션은 반응형보다 나빠진다. 본 연구는 Pallas의 사용자별 목적함수를 합으로 묶고 자원 결합을 명시한 타겟 단위 공동 계획 문제를 정의하고, 계획 점유 위의 유체 완료 모델과 외부효과 비용으로 트리거를 분산하는 데드라인 순 탐욕 스케줄러를 제안하였다. 제안은 후보가 하나일 때 Pallas와 동일한 결정을 내리는 일반화이며, 32–192명 플래툰 환경에서 평균 SIT를 15–53%, p99를 70–76% 줄이고 동시 스트림 첨두를 반응형 수준으로 억제하며, 소규모 인스턴스에서 최적 대비 7–8% 안에 든다. 향후 실제 궤적과 소규모 프로토타입 측정으로 배칭 병렬도·활성화 직렬화 가정을 확인하고, VRAM을 계획에 포함하는 확장과 국소 탐색으로 탐욕 격차를 줄이는 것이 남은 과제이다.

# 다중 사용자 이동성 환경 엣지 LLM 서빙을 위한 조율형 선제 KV 마이그레이션: 비조율 선제 스케줄러의 Herding 한계를 넘어서

> 작업 중 초안 (v0.3) — 팀 공통 주제 MEC 하위, 서브주제 "이동성 기반 서비스 마이그레이션 × LLM".
> 방식: 타겟 논문 1편 지정 후 알고리즘/아이디어 개선(방식 B).
> v0.3 변경 요지: Pallas [pallas]의 존재를 반영하여 novelty 축을 이동하였다. v0.2까지의 주장("반응형 스케줄러는 시간축 개입이 불가하므로 선제적 프리페치가 필요하다")은 Pallas가 실제 vLLM 프로토타입으로 이미 확립하였다. 따라서 본 연구의 개선 대상은 반응형 ctHO [target]가 아니라 선제형 Pallas이며, novelty는 "선제성" 자체가 아니라 **공유 자원(백홀 링크·타겟 GPU·VRAM)을 놓고 경쟁하는 다중 사용자의 선제 마이그레이션을 조율(coordination)하는 결정**에 둔다. Pallas는 이를 명시적으로 범위 밖("general multi-user resource allocation remains outside the scope")으로 두었다.

## 1. 서론

### 1-1. 연구 배경

멀티액세스 엣지 컴퓨팅(MEC)과 그 무선접속망 확장인 AI-RAN은 GPU를 기지국(gNB)에 병설하여 대규모 언어 모델(LLM) 서빙을 사용자 인접 지점으로 끌어온다 [survey1, survey2]. LLM 서빙은 기존 MEC의 상태 없는(stateless) 태스크 오프로딩과 근본적으로 다르다. LLM은 자기회귀적으로 토큰을 생성하며 지금까지의 문맥을 키-값 캐시(KV 캐시)라는 상태로 GPU 메모리에 유지한다. Qwen3-32B의 경우 토큰당 약 256 KiB, 4,000 토큰 문맥에서 약 1 GiB에 이르며, 이 상태는 디코딩이 진행되는 동안 매 토큰 계속 자란다 [pallas]. 사용자가 셀 경계를 넘어 서빙 gNB가 바뀌면(핸드오버) 상태는 원 서버에 남고 사용자는 새 서버에 붙으므로, 세션을 이어가려면 상태를 어떻게든 새 서버에 마련해야 한다.

### 1-2. 문제 제기: 반응형에서 선제형으로, 그리고 남은 문제

핸드오버 후 타겟에서 KV 캐시를 복원하는 방법은 세 가지 계열로 정리된다. 전량 전송(Full-Copy), 원본 토큰만 넘겨 타겟에서 prefill로 재계산(Recomputation), 그리고 둘을 결합하여 prefix는 재계산·suffix는 전송하고 다중 사용자 간 백홀 대역폭까지 함께 배분하는 ctHO [target]이다. 이들은 모두 **핸드오버가 일어난 뒤에야 복구를 시작하는 반응형(reactive)** 이라는 시간 구조를 공유하며, 복구 시간이 그대로 서비스 중단 시간(Service Interruption Time, SIT)이 된다.

Pallas [pallas]는 이 시간 구조를 깨뜨렸다. 이동 예측으로 타겟 gNB와 핸드오버 시각 $\hat{t}_{HO}$를 추정하고, 핸드오버를 "복구의 트리거"가 아니라 "준비의 데드라인"으로 취급한다. 트리거 시점에 토큰열을 안정 prefix(타겟에서 prefill 재계산)와 진화하는 suffix(소스에서 KV 블록 스트리밍)로 나누고, 두 작업을 소스의 디코딩과 병행한다. 온라인 스케줄러는 관측된 유효 prefill 처리량·디코딩 속도·백홀 goodput으로 prefetching window $T_w$를 선택한다. vLLM 프로토타입에서 ctHO 대비 SIT를 2.3–6.8배 줄였다. 즉 "선제성"이라는 결정 축은 이미 점유되었고, 단일 사용자 관점에서의 핸드오버 문제는 상당 부분 해소되었다.

그러나 Pallas의 스케줄러는 **사용자별로 독립적으로** 동작한다. 여러 사용자가 같은 타겟을 향할 때 각자의 $T_w^*$는 (i) 동일한 목적함수, (ii) 동일한 관측 자원 상태, (iii) 근접한 $\hat{t}_{HO}$로부터 계산되므로 거의 같은 값이 나오고, 결과적으로 거의 같은 순간에 트리거된다. N개의 prefix prefill이 타겟 GPU로, N개의 suffix 스트림이 같은 백홀 링크로 동시에 몰린다. **첨두는 사라진 것이 아니라 핸드오버 시점에서 prefetching window 시점으로 옮겨진 것이다.** 게다가 Pallas가 경합을 인지하는 경로는 EWMA로 평활한 *관측* 유효율($r_p, B$)뿐이다. 이는 경합이 시작된 뒤에야 낮아지는 지연 지표이므로, Pallas는 핸드오버에 대해서는 선제적이지만 **경합에 대해서는 여전히 반응형**이다. 논문 자신도 "GPU 사이클이나 gNB 간 대역폭을 동시 마이그레이션 간에 공동 배분하지 않으며, 일반적 다중 사용자 자원 배분은 범위 밖"이라고 명시하고, 결론에서 "동적 다중 사용자 경합 하의 공동 자원 배분과 window 재계획"을 향후 연구로 남겼다. 동시성 실험도 같은 타겟으로 K ≤ 4명에 그친다.

본 연구는 바로 이 자리를 다룬다. 이동성이 공간·시간적으로 상관된 환경(차량 플래툰, 버스, 열차, 출퇴근 흐름)에서 수십~수백 사용자의 핸드오버가 근접 시점·동일 방향으로 겹칠 때, 비조율 선제 스케줄링이 만드는 herding을 규명하고, 타겟 단위로 프리페치 시점·suffix 처리 방식·prefill 순서·VRAM 승인·migrate/detour 선택을 공동 결정하는 조율형 선제 마이그레이션을 제안한다.

### 1-3. 연구 공헌

- 첫째(문제 규명), 선제형 KV 마이그레이션의 대표인 Pallas가 사용자별 독립 결정과 관측 기반 경합 추정이라는 두 구조적 가정 때문에, 다중 사용자 핸드오버가 시간적으로 겹치는 구간에서 첨두를 제거하지 못하고 시간축 상에서 이동시킬 뿐임(herding)을 규명한다. 이 한계가 파라미터($T_{\max}$, $\alpha$, EWMA 계수) 재조정으로 해소되지 않는 **결정 구조(비조율)의 문제**임을 통제실험으로 뒷받침한다.
- 둘째(핵심 기여), Pallas의 사용자별 목적함수를 그대로 두되, 타겟 단위에서 모든 후보 사용자의 트리거 시점을 데드라인 순으로 공동 계획하는 조율형 스케줄러를 제안한다. 계획된(관측이 아닌) 동시성 계수 $k$로 비용을 평가하고 동시성 상한 하에서 시간축 분산(staggering)하며, 링크 부하 계획에 따라 사용자별 suffix 처리(스트리밍 vs 지연 재계산)를 선택하고, 타겟 GPU는 EDF 순으로 prefill을 서비스하며, VRAM 예산으로 조기 준비를 승인하고, 예측 불일치·핑퐁 핸드오버에는 migrate 대신 detour를 택한다. 경합이 없는 구간($k=1$)에서는 Pallas와 동일한 결정으로 수렴한다.
- 셋째(비교 검증), 동일한 예측기·동일한 비용 모델·동일한 자원 모델 하에서 Full-Copy, Recomputation, ctHO, Detour, Pallas 근사, 제안 방법을 비교하고, Pallas 프로토타입(GPU 2대, K ≤ 4)이 다룰 수 없는 규모(서버 6개, 사용자 16–128명, 플래툰 이동)에서 밀도 스윕을 수행한다.
- 넷째(다층 검증), Pallas의 SIT/ITL/$T_{\mathrm{early}}$/$T_{\mathrm{waste}}$에 다중 사용자 구조를 직접 포착하는 지표(링크별 동시 스트림 첨두, 링크 요구량 첨두, 시간축 부하 변동계수, worst-user SIT)를 더한 지표 계층을 제시한다.

## 2. 관련 연구

### 2-1. LLM 서빙 시스템의 KV 캐시 관리
연속 배칭 [orca], PagedAttention [vllm], 데이터센터 내 요청 마이그레이션 [llumnix], 토큰 기반 상태 복원 [sllm], KV 압축·스트리밍 [cachegen] 등이 KV 캐시를 옮기거나 재구성하는 기본 메커니즘을 제공한다 [kvsurvey, kvsched, mtds]. 그러나 이들은 데이터센터 내부의 처리량·메모리 최적화를 목표로 하며, 무선 이동성에 의한 서버 간 세션 연속성이나 대역폭이 제한된 gNB 간 링크는 고려하지 않는다.

### 2-2. 이동성 기반 서비스 마이그레이션
핸드오버 예측과 서비스 마이그레이션의 결합 [hopred], 궤적 예측·심층강화학습 기반 선제 마이그레이션 [srcl, magrl, mapsm], 5G 상태 유지 애플리케이션의 즉시 이동성 [warp] 등이 제안되어 왔다. 이들은 상태를 고정 크기 객체로 가정하며, LLM 세션 특유의 (i) 토큰 수에 비례하고 준비 중에도 계속 자라는 상태, (ii) 전송의 대안인 재계산(prefill)이라는 선택지를 다루지 않는다.

### 2-3. 엣지 LLM 핸드오버(직접 관련)
ctHO [target]는 prefix 재계산과 suffix 전송을 결합하고 다중 사용자 간 백홀 대역폭을 배분하여 worst-user 핸드오버 지연을 최소화하는 반응형 joint 스케줄러이다. ILCP [ilcp]는 순환 상태를 압축 전송하여 콜드 스타트를 완화한다. Pallas [pallas]는 이동 예측으로 핸드오버 전에 상태 준비를 시작하는 선제형 프레임워크로, 안정 prefix 재계산과 진화 suffix 스트리밍을 소스 디코딩과 병행하고, prefetching window를 온라인으로 선택하며, 예측 변경 시 epoch 기반 취소와 낭비 상한을 제공한다. DAPO [dapo]는 이동성을 고려하나 모델 분할에 초점을 두어 문제 축이 다르다.

### 2-4. 본 연구의 위치
아래 표는 결정 시점과 결정 범위라는 두 축으로 관련 연구를 배치한 것이다. 본 연구는 Pallas와 결정 시점을 공유하되 결정 범위를 사용자별 독립에서 타겟 단위 공동으로 확장한다는 점에서 구별된다. ctHO가 "반응형 × 다중 사용자 joint"였다면, 본 연구는 "선제형 × 다중 사용자 joint"의 빈 칸을 채운다.

| | 사용자별 독립 결정 | 다중 사용자 공동 결정 |
|---|---|---|
| 반응형(핸드오버 후 복구) | Full-Copy, Recomputation | ctHO [target] |
| 선제형(핸드오버 전 준비) | Pallas [pallas] | **본 연구** |

## 3. 시스템 모델 및 문제 진단

### 3-1. 시스템 모델
2차원 평면에 배치된 gNB 병설 엣지 서버 집합 $\mathcal{M}$과 이동 사용자 집합 $\mathcal{K}$를 고려한다. 서버 $m$은 prefill 처리량 $v_m$(토큰/초)의 GPU, 용량 $B_m$(바이트/초)의 ingress 백홀 링크, 그리고 조기 준비 상태에 빌려줄 수 있는 VRAM 예산 $V_m$을 가진다. 사용자 $k$의 문맥 길이 $L_k(t)$는 디코딩 속도 $r_d$로 증가하며 KV 크기는 $c\,L_k(t)$이다. 사용자는 서빙(무선) 서버 $s_k(t)$와 상태를 보유한 앵커 서버 $a_k(t)$를 구별하여 가진다. 둘이 다르면 소스가 디코딩을 계속하고 토큰을 포워딩하는 Detour 상태이며, 홉 수에 비례하는 토큰 간 지연(ITL) 페널티를 받는다 [pallas].

### 3-2. 단일 사용자 비용 모델
**반응형(ctHO).** 핸드오버 시점에 $L$ 토큰 중 $p$를 재계산, $L-p$를 전송하면 두 작업이 병렬이므로

$$
D(p)=\max\!\left(\frac{p}{v},\ \frac{c\,(L-p)}{B}\right),\qquad
p^\star=\frac{c\,v\,L}{B+c\,v},\qquad
D^\star=\frac{c\,L}{B+c\,v}.
$$

**선제형(Pallas).** 예측 핸드오버 시각까지 남은 시간 $\hat{T}_{\mathrm{remain}}$에서 window $T_w$를 택하면 트리거 시점의 prefix 길이는 $\hat{L}_{\mathrm{hist}}(T_w)=K+r_d(\hat{T}_{\mathrm{remain}}-T_w)$이고,

$$
T_{\mathrm{hist}}=\frac{\hat{L}_{\mathrm{hist}}}{r_p},\qquad
T_{\mathrm{res}}(T_w)=\max\!\left\{0,\ \frac{r_d\,T_w\,c}{B}-T_w\right\},
$$

$$
T_{\mathrm{SIT}}(T_w)=T_0+\max\{0,\ T_{\mathrm{hist}}-T_w,\ T_{\mathrm{res}}(T_w)\},\qquad
T_{\mathrm{early}}(T_w)=\max\{0,\ T_w-T_{\mathrm{hist}}\},
$$

$$
T_w^\star=\arg\min_{T_w\in[0,\min(T_{\max},\hat{T}_{\mathrm{remain}})]}\ \alpha\,T_{\mathrm{SIT}}(T_w)+(1-\alpha)\,T_{\mathrm{early}}(T_w).
$$

여기서 $r_p, B$는 **관측된** 유효율(타겟 GPU·링크의 현재 경합을 반영해 EWMA로 평활한 값)이다. 핸드오버 시점에 남은 prefix와 미전송 suffix가 SIT를 결정한다.

### 3-3. 다중 사용자 자원 모델
타겟 $m$을 향해 동시에 진행 중인 준비·복구의 수를 $n_m(t)$라 하면, GPU는 $v_m$을 정책이 정한 순서(기본 FCFS)로 분배하고 링크는 백로그를 가진 스트림 사이에 $B_m$을 공정 분배한다. 즉 사용자 하나가 겪는 유효율은

$$
r_p^{\mathrm{eff}}(t)\approx\frac{v_m}{n_m^{\mathrm{prefill}}(t)},\qquad
B^{\mathrm{eff}}(t)\approx\frac{B_m}{n_m^{\mathrm{stream}}(t)}
$$

이며, 핸드오버 후 반응형 복구와 핸드오버 전 선제 준비가 **같은 자원을 놓고 경쟁한다**. 선제 프리페치는 공짜가 아니다. 그 스트림이 링크를 점유하는 동안 같은 링크로 들어오는 다른 사용자의 잔여 복구가 느려진다. v0.2까지의 초안과 시뮬레이터는 이 항을 무시했으며(프리페치 전송량을 핸드오버 순간 부하에서 차감만 함), 백홀 혼잡을 주장하려면 이 항이 필수이다.

### 3-4. 비조율 선제 스케줄링의 Herding 메커니즘
같은 플래툰의 $N$명이 타겟 $m$을 향해 근접한 $\hat{t}_{HO}$를 가진다고 하자. Pallas 스케줄러는 사용자별로 3-2절의 $T_w^\star$를 계산하는데, 입력인 $K$, $\hat{T}_{\mathrm{remain}}$, 관측 $r_p, B$가 모두 비슷하므로 출력도 비슷하다. 그 결과 $N$명이 거의 같은 순간에 트리거되고, window 동안 실제 유효율은 $v_m/N$, $B_m/N$으로 떨어진다. 그러나 각 사용자는 $T_w^\star$를 선택할 때 $N=1$에 가까운 과거 관측치를 사용했으므로 $T_{\mathrm{hist}}$를 $N$배 과소 추정했고, window 안에 prefix를 마치지 못한 채 핸드오버를 맞는다. 잔여 prefix는 반응형 재계산과 같은 경로로 SIT에 들어간다. 관측 EWMA가 그제야 낮아지면 다음 플래툰은 과도하게 긴 window를 택해 $T_{\mathrm{early}}$와 VRAM 점유를 늘리는 진동이 생긴다.

요약하면 비조율 선제 스케줄링은 (i) 첨두를 제거하지 않고 시간축에서 앞으로 옮기며, (ii) 관측 기반 경합 추정은 지연 지표이므로 첨두 형성을 예방할 수 없고, (iii) 준비 스트림이 반응형 복구 트래픽과 링크를 경쟁하여 예측이 없는 사용자에게 외부 비용을 떠넘긴다. 이는 정책 파라미터가 아니라 **결정 범위(사용자별 독립)** 에서 비롯된다.

**통제실험.** 이를 확인하기 위해 고밀도 플래툰 조건에서 Pallas 근사의 파라미터를 재탐색한다: $T_{\max}$ 5→15 s, $\alpha$ 0.8→0.5, EWMA 계수 0.5→0.95(빠른 관측 반응). 재조정 후에도 동시 스트림 첨두와 SIT p99가 개선되지 않으면(5-4절 pilot 결과 참조), 한계가 조정 부족이 아니라 결정 구조에서 기인한다는 주장이 뒷받침된다.

## 4. 제안 방법: 타겟 단위 조율형 선제 마이그레이션

### 4-1. 설계 목표와 원칙
(i) **조율**: 같은 타겟을 향하는 사용자들의 window를 공동 계획하여 계획된 동시성이 상한 $k_{\max}$를 넘지 않게 시간축으로 분산한다. (ii) **계획 기반 경합 추정**: 관측 EWMA 대신, 이미 트리거된 준비와 지금 계획 중인 준비가 각 시간 구간에 몇 개 겹치는지(occupancy)로 유효율을 산정한다. 지연 지표가 아닌 선행 지표이다. (iii) **Pallas로의 수렴**: 후보가 하나이고 활성 준비가 없으면 $k=1$이 되어 Pallas의 $T_w^\star$와 같은 결정을 내린다. 즉 제안은 Pallas의 일반화이다. (iv) **경량·학습 불필요**: 예측기와 사용자별 목적함수는 Pallas 것을 그대로 쓰고, 추가 연산은 타겟별 후보 수 × 시간 구간 수의 스칼라 연산이다.

### 4-2. 구성 요소
- **타겟 단위 계획기.** 매 제어 주기, 타겟 $m$을 향해 예측된 후보를 $\hat{t}_{HO}$ 오름차순(EDF)으로 정렬한다. 시간축을 $\Delta t$ 구간으로 나눈 occupancy 배열에 이미 활성인 준비를 먼저 채운 뒤, 각 후보에 대해 트리거 후보 시점 $s$를 데드라인에서 과거로 훑으며 window $T_w=\hat{T}_{\mathrm{remain}}-s$에 대한 계획 동시성 $k=1+\max\,\mathrm{occ}[s{:}\,\hat{T}_{\mathrm{remain}}]$을 구하고, $k\le k_{\max}$인 후보 중 아래 비용을 최소화하는 $s$를 택한다. 선택된 구간을 occupancy에 반영한 뒤 다음 후보로 넘어간다. $s=0$인 후보만 이번 주기에 트리거한다.
- **계획 동시성 기반 비용.** Pallas 목적함수를 $r_p=v_m/k$, $B=B_m/k$로 평가한다:

$$
\mathcal{J}_k(T_w)=\alpha\,T_{\mathrm{SIT}}\!\left(T_w;\ \tfrac{v_m}{k},\ \tfrac{B_m}{k}\right)+(1-\alpha)\,T_{\mathrm{early}}\!\left(T_w;\ \tfrac{v_m}{k}\right).
$$

- **suffix 처리 모드 선택.** window 동안 생성되는 suffix를 스트리밍할지($T_{\mathrm{res}}^{\mathrm{stream}}$), 스트리밍하지 않고 핸드오버 시점에 짧은 suffix를 최적 분할로 재계산·전송할지($T_{\mathrm{res}}^{\mathrm{defer}}$)를 사용자별로 정한다. 계획된 집계 스트림 속도 $k\,r_d\,c$가 링크 용량의 $\rho$ 배를 넘으면 스트리밍을 금지한다. 이는 링크 첨두를 낮추는 대신 소량의 재계산을 받아들이는 트레이드오프이다.
- **EDF prefill 서비스.** 타겟 GPU는 준비 중인 prefix들을 트리거 순(FCFS)이 아니라 데드라인 순으로 서비스한다. 임박한 사용자가 먼저 끝나므로 같은 총 처리량에서 잔여 prefix가 SIT로 넘어가는 양이 줄어든다.
- **VRAM 승인.** 타겟에 이미 준비된 상태의 합이 $V_m$을 넘으면 트리거를 보류한다. 다수의 조기 prefix가 타겟 메모리를 점유하는 문제는 단일 사용자 Pallas에서는 나타나지 않는다.
- **migrate 대신 detour.** 예측이 없었거나 예측과 다른 타겟으로 핸드오버가 발생한 경우, 또는 최근 떠난 서버로 되돌아가는 핑퐁인 경우, 준비되지 않은 상태를 반응형으로 복구하는 대신 홉 상한 $h_{\max}$까지 Detour를 택한다. 일정 시간($\tau_{\mathrm{settle}}$) 머무르면 데드라인 없는 배경 마이그레이션으로 상태를 서빙 서버로 옮긴다(settle). 반응형 복구 트래픽을 첨두에서 제거하는 대신 일시적 ITL 상승을 받는다.
- **예측 신뢰도 게이트.** 후보 타겟과 차순위 타겟의 거리 차가 임계 이하인 사용자는 이번 주기 계획에서 제외한다(Pallas의 $T_{\mathrm{waste}}$에 대응하는 낭비 억제).

### 4-3. 알고리즘 개요
매 제어 주기 $t$:
1. 활성 준비 갱신: 예측 타겟이 바뀐 준비는 취소(epoch 증가), 시각만 바뀐 준비는 데드라인 갱신.
2. Detour 상태로 $\tau_{\mathrm{settle}}$ 이상 머문 사용자는 서빙 서버로 settle 마이그레이션 트리거.
3. 타겟별 후보 수집 → 4-2 계획기 실행 → $s=0$이고 VRAM 승인을 통과한 사용자만 트리거(모드 포함).
4. 자원 진행: GPU는 EDF로 prefix 서비스, 링크는 스트림 공정 분배, 소스 디코딩으로 suffix 증가.
5. 핸드오버 발생 시: 준비가 타겟과 일치하면 잔여(미완 prefix + 미전송 suffix)를 최적 분할로 복구; 불일치·핑퐁이면 detour 또는 반응형 하이브리드.

계산 복잡도는 타겟당 $O(|\mathcal{C}_m|\cdot H/\Delta t)$(후보 수 × 계획 지평 구간 수)의 스칼라 연산으로, Pallas의 $O(T_{\max}/\Delta T)$ 그리드 탐색에 후보 수만큼 곱해진 수준이다.

## 5. 실험 설계 및 Pilot 결과

### 5-1. 지표 계층화
- **주 지표(Pallas·ctHO와 직접 비교 가능)**: SIT 평균/p99/최대(worst-user), ITL 평균(Detour 비용).
- **구조 지표(다중 사용자 메커니즘 직접 포착)**: 링크별 동시 스트림 첨두, 링크 요구량 첨두(MB/s), 시간축 링크 요구량의 변동계수(CoV, 버스트성), $T_{\mathrm{early}}$ 평균, 취소로 낭비된 준비량(MB).
- **부가 지표**: 총 전송량, detour 횟수, 핑퐁 횟수, 핸드오버 수.

### 5-2. 베이스라인
Full-Copy / Recomputation / ctHO 근사(핸드오버 시점 최적 분할, 다중 사용자 공정 분배) / Detour / **Pallas 근사**(사용자별 $T_w^\star$ 그리드 탐색, 관측 EWMA 유효율, prefix prefill FCFS + suffix 스트리밍, 타겟 변경 시 취소) / 제안(조율형). 모든 정책은 동일한 CVH 예측기, 동일한 궤적·토큰·예측 트레이스, 동일한 자원 모델을 공유한다(paired comparison).

### 5-3. 환경과 보정
파라미터는 Pallas 공개 수치로 보정한다: $c$=256 KiB/토큰(Qwen3-32B BF16), $v_m$≈2,000 토큰/초, $r_d$=15 토큰/초, 링크 300 Mbps, 문맥 500–4,500 토큰, $T_0$=150 ms, $\alpha$=0.8, $T_{\max}$=5 s. 서버 6개(3×2), 1 km², 셀 반경 320 m, 사용자 16–128명, 플래툰 크기 8, 속도 25 m/s, 600 s. 이동 모델은 플래툰 직선 흐름(GroupFlow)과 랜덤 웨이포인트(RWP)를 제공하며, 본실험에서는 실제 궤적(nuScenes, T-Drive, Rome/Porto taxi)으로 교체한다. 상세는 `sim/`.

### 5-4. Pilot 결과(방향성 확인용, seed 1개)

## 6. 한계와 향후 과제

- **시뮬레이션 기반.** Pallas는 실제 vLLM 프로토타입으로 검증하였다. 본 연구는 수십~수백 사용자 규모라는 프로토타입이 다룰 수 없는 영역을 다루지만, 단일 사용자·소규모 동시성 구간에서 시뮬레이터가 Pallas 공개 수치(Table 1·2, Fig. 5·8)를 재현함을 먼저 보여 보정의 신뢰를 확보해야 한다. 특히 Pallas의 K=1–4 HH 실험(SIT 236–292 ms, worst-user 237–359 ms)을 시뮬레이터로 재현하는 것이 첫 과제이다.
- **자원 모델의 단순성.** prefill 처리량을 동시 작업 수로 균등 분할하고 링크를 공정 분배로 근사하였다. chunked prefill과 상주 디코딩 요청(Pallas의 HI 경합)과의 상호작용, 링크의 프로토콜 오버헤드는 반영되지 않았다.
- **예측기.** CVH 외삽만 사용하였다. 예측 신뢰도를 계획에 반영하는 방식(확률 가중 다중 후보 준비, 헤징)은 열린 문제이며 4-2의 신뢰도 게이트는 그 최소 형태이다.
- **Detour 비용.** 홉당 고정 ITL 페널티로 근사하였고 소스 GPU에 남는 상주 세션의 메모리·연산 비용은 반영하지 않았다.
- **조율의 저경합 오버헤드.** 경합이 없는 구간에서 제안이 Pallas보다 약간 보수적인데, $k=1$일 때 Pallas와 정확히 일치하도록 계획 격자·게이트를 정리해야 한다.
- **공정성.** 데드라인 순 계획은 늦게 도착한 사용자를 뒤로 미룬다. worst-user SIT와 Jain 공정성 지수를 본실험 지표에 포함한다.

## 7. 결론(예정)
사용자 이동으로 서빙 엣지 서버가 바뀔 때 LLM 세션의 KV 캐시를 잇는 문제에서, 선제형 마이그레이션(Pallas)은 핸드오버를 준비의 데드라인으로 바꾸어 단일 사용자 SIT를 크게 낮추었다. 그러나 사용자별 독립 결정과 관측 기반 경합 추정은 다중 사용자 핸드오버가 겹치는 구간에서 첨두를 제거하지 못하고 앞으로 옮길 뿐이며, 이는 파라미터 재조정으로 해소되지 않는다. 본 연구는 Pallas의 사용자별 목적함수를 유지하면서 타겟 단위로 트리거 시점·suffix 모드·prefill 순서·VRAM 승인·migrate/detour를 공동 결정하는 조율형 선제 마이그레이션을 제안하고, Pallas가 명시적으로 범위 밖으로 둔 다중 사용자 자원 조율 문제를 그 프레임워크의 자연스러운 일반화로 다룬다. 향후 실제 궤적과 Pallas 공개 수치에 대한 보정을 거친 본실험으로 재현성과 통계적 신뢰도를 확보한다.
